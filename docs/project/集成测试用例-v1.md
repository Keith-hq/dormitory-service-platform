## 0. 契约口径（判定标准的地基，执行前必读）

| 项 | 约定 |
|---|---|
| 统一响应 | `{ code, message, data }`；**code=0/200 成功**，非 0 为业务错误码（区分错误类型） |
| 分页 | 参数 `page/pageSize`，返回 `{ items, total, page, pageSize }` |
| 鉴权 | 登录 `POST /auth/login` 拿 token，后续接口带 `Authorization: Bearer <token>` |
| 幂等 | **`Idempotency-Key` 请求头**（契约显式标注）：STU-05 缴费、STU-07 充值、STU-25 借用、DORM-29 耗材出库 |
| data 未展开 | 多数 POST 的 `data` 字段契约未定义 → **成功以 code=0/200 判定，业务结果一律用后续 GET + DB 断言验证**，不猜响应字段 |
| 遗留双路径 | `/api/notices`、`/api/buildings`、`/api/facilities`、`/api/feesharing/*` 为遗留接口（无编号）；前端统一走编号接口，C10 专门校验 |

> ⚠️ **operationId 后缀约定（契约核实 08-12）**：部分 CRUD 组 operationId 带动作后缀、**无裸编号**——`SUPER-01/02`（`-create/-delete/-list/-update`）、`SUPER-03`（`-create/-list/-update`）、`DORM-01` 另有 `-detail`、`DORM-02`（`-create/-update`）、`DORM-14`/`DORM-43`/`DORM-49`（`-delete/-update`）。本文与认领表用裸编号作简称，**执行时以 Apifox 契约的 operationId 为准**。
> **契约核实口径（08-12）**：对照 `默认模块.openapi.json`（178 operation / 160 编号 + 9 遗留 path + 已展开的编号组）逐条核对过本文用例的接口引用——除上述后缀组外全部命中；`calc-checkout` 确认是**遗留路径**（`POST /api/feesharing/calc-checkout`，query: studentId、allocationId），与 `DORM-36 开始清算` 分属分摊域/退宿域，见 C10-004 与看板分工待办。

### 4.1 C1 认证与权限（P0 · 徐亦尘）

#### IT-C1-001 各角色登录 / 锁定与验证码 ｜ FP1-1 ｜ P0 ｜ 执行:＿＿ ｜ 结果:＿＿
**场景**: 四角色登录是否各归各工作台；错误密码与锁定机制是否生效。
**接口链**: `GET /auth/captcha` → `POST /auth/login` `{loginName, password}`
**前置与测试数据**: 学生 IT_STU_001、宿管 IT_ADMIN_001、辅导员 IT_COUN_001、超管各一，密码已知。
**数据样本**:
```
【登录】POST /auth/login   { "loginName":"IT_STU_001", "password":"<初始密码>" }
→ 预期: code=0，data 含 token 与角色
【错密码×5】重复 POST /auth/login（错误密码）
→ 预期: code≠0、message 可读；第 5 次后触发锁定并强制验证码
【带验证码】GET /auth/captcha → 再 POST /auth/login
→ 预期: 验证码通过后可登录
```
**通过判定**:
① 四角色均登录成功 code=0，且工作台与角色匹配；
② 错密码返回业务错误码（非 500）；
③ 连错 5 次锁定 + 必须验证码，锁定状态落库；
④ DB: 审计表有登录行为记录（含失败尝试）。

#### IT-C1-002 角色访问控制矩阵（越权） ｜ FP1-1 ｜ P0 ｜ 执行:＿＿ ｜ 结果:＿＿
**场景**: 低权限角色访问高权限接口是否被拒。
**接口链**: `GET /buildings`（宿管 DORM-01）｜ `GET /students`（超管 SUPER-03）｜ `GET /reports/{type}`（超管 REPT-01）｜ `GET /admins/{adminId}/repair-tickets`
**前置与测试数据**: 学生 token、宿管 token、普通学生 token。
**数据样本**:
```
学生 token → GET /buildings      → 预期: 403, code≠0
学生 token → GET /students       → 预期: 403, code≠0
宿管 token → GET /reports/{type} → 预期: 403, code≠0
```

#### IT-C1-003 首登强制改密 / token 生命周期 ｜ FP1-1 ｜ P0 ｜ 执行:＿＿ ｜ 结果:＿＿
**场景**: 新账号首登改密、改密后旧 token 失效、退出后 token 不可复用。
**接口链**: `POST /accounts/students` → `POST /auth/login` → `PUT /auth/password` → `GET /auth/me` → `POST /auth/logout`
**前置与测试数据**: 新开通学生账号（AUTH-04 或 IMPORT 联动）。
**数据样本**:
```
【开通】POST /accounts/students { "studentId":"IT_STU_005", "initialPassword":"123456" }
【首登】POST /auth/login → 改密前调任一业务接口 → 预期: 被拦（强制改密）
【改密】PUT /auth/password { "oldPassword":"123456", "newPassword":"newPass@1" }
【验证】旧密码登录 → 预期: 失败；新密码登录 → 成功
【退出】POST /auth/logout → 复用旧 token 调 GET /auth/me → 预期: 401
```
**通过判定**:
① 首登未改密前业务接口被拦；
② 改密后旧密码登录失败、新密码成功；
③ 退出后旧 token 失效（401）；
④ DB: 密码非明文存储。

### 4.2 C2 退宿清算闭环（P0 · 刘润东×李昂×兰皓衍）— 跨人链路

#### IT-C2-001 退宿清算全链路（happy path + 幂等） ｜ FP3-16 ｜ P0 ｜ 执行:＿＿ ｜ 结果:＿＿
**场景**: 入住→退宿登记→结算→开始清算→确认退宿→释放床位→通知，全链路。
**接口链**: `POST /allocations` → `POST /allocations/{id}/checkout-register` → `POST /api/feesharing/calc-checkout?studentId=&allocationId=` → `GET /checkouts/{checkoutId}` → `POST /checkouts/{id}/settle` → `POST /checkouts/{id}/confirm` `{checkoutDate}`
**前置与测试数据**: IT_STU_001 入住 900101（bedNo 1）；有未结水电账单；分摊已产生。
**数据样本**:
```
【入住】POST /allocations { "studentId":"IT_STU_001", "roomId":900101, "bedNo":1, "checkInDate":"2026-08-01" } → 记 allocationId
【退宿登记】POST /allocations/{allocationId}/checkout-register { "reason":"毕业退宿", "checkoutDate":"2026-08-12" } → 记 checkoutId
【结算×2】POST /api/feesharing/calc-checkout?studentId=IT_STU_001&allocationId={id}  → 连调两次，记录两次金额
【开始清算】POST /checkouts/{checkoutId}/settle
【确认退宿×2】POST /checkouts/{checkoutId}/confirm { "checkoutDate":"2026-08-12" } → 再调一次
【终态】GET /checkouts/{checkoutId}
```
**通过判定**:
① 每步 code=0/200；
② **calc-checkout 连调两次金额一致、不重复扣款**（幂等）；
③ **confirm 重复执行不报错**（幂等）；
④ `GET /checkouts/{checkoutId}` 终态=已清算；
⑤ DB: `D_Allocation` 状态=已退宿、房间占用数-1；无重复结算记录；
⑥ 学生 `GET /notifications` 可见清算通知。

#### IT-C2-006 调寝原子性（旧房-1 新房+1） ｜ FP3-2 ｜ P1 ｜ 执行:＿＿ ｜ 结果:＿＿
**场景**: 调寝时新旧房间占用数在同一事务内增减，不出现不一致。
**接口链**: `POST /allocations/{allocationId}/transfer` `{targetRoomId, targetBedNo}`
