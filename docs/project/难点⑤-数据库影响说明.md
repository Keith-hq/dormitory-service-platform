## 2. 变更明细

### 2.1 `D_Repair_Ticket.Escalation_Time DATE`

- **语义**：`NULL` = 从未升级；`NOT NULL` = 已升级（防二次升级的唯一事实来源）。
- **写入方**：`SP_Escalate_SLA`（条件 UPDATE `WHERE Escalation_Time IS NULL` + `SQL%ROWCOUNT` 守门，多实例并发安全）。
- **读取方**：DORM-26 待处理列表（DTO `EscalationTime` 字段，仅展示）。
- **受影响接口**：`GET /api/admins/{adminId}/repair-tickets`（DORM-26）、`POST /api/internal/scheduler/sla-escalation`（SVC-SCHED-03）、Quartz `SlaEscalationJob`（每 15 分钟）。
- **回滚**：`ALTER TABLE D_Repair_Ticket DROP COLUMN Escalation_Time;`（需先停用 SLA 升级巡检）。

### 2.2 `D_Repair_Log.Repair_Result VARCHAR2(200)`

- **语义**：维修结果枚举（契约 DORM-28）：`已修复` / `需更换配件` / `无法修复`；可空（历史数据/未提供时 NULL）。
- **写入方**：`SP_Complete_Repair` 参数 `p_Repair_Result`（C# 侧已做枚举校验）。
- **受影响接口**：`POST /api/repair-tickets/{ticketId}/logs`（DORM-28，请求字段 `repairResult`）。
- **回滚**：`ALTER TABLE D_Repair_Log DROP COLUMN Repair_Result;`

### 2.3 `CK_D_REPAIR_TICKET_STATUS`

- **定义**：`CHECK (Status IN ('待处理','处理中','已完成'))`。
- **影响**：`SP_Claim_Ticket`（待处理→处理中）、`SP_Complete_Repair`（处理中→已完成）写入路径的兜底校验；非法状态写入将被拒绝（ORA-02290）。
- **重跑行为**：SP 脚本内补丁捕获 `ORA-02264`（同名约束已存在）幂等跳过——三审前误捕获 `-2260` 已修正。

### 2.4 `CK_D_ADMIN_ROLE`

- **定义**：`CHECK (Role_Level IN ('楼长','维修员','超级管理员'))`。
- **影响**：`SP_Assign_Ticket`/`SP_Escalate_SLA` 按 `Role_Level` 查询维修员/楼长，约束保证角色域一致；与 `AuthPolicies` 的 role claim 映射（admin→楼长、repairman→维修员、super_admin→超级管理员）配套。
- **重跑行为**：同上，捕获 `ORA-02264`。

## 4. 三审相关变更说明（SP 行为变化）

- **不再写 `D_Notification`**：原 `MAX(Notification_ID)+1` 双实例并发会撞主键，且通知数据属于通知中心模块（拥有者边界）。现由 `SP_Escalate_SLA` 通过 `SYS_REFCURSOR` 返回本次新升级工单清单，应用层 `SlaDispatchService` 调用公共服务 `INotificationService.CreateAsync` 投递（其内部使用通知模块自己的主键机制）。
- **不再写 `D_Audit_Event`**：同理，`MAX(Audit_ID)+1` 并发撞主键；审计序列方案见 §0 待确认事项 #2。升级痕迹可由 `Escalation_Time` + 通知记录推导。
- **并发模型**：`FOR UPDATE SKIP LOCKED`（按 `Ticket_ID` 排序固定加锁顺序，避免双实例交叉死锁）+ 条件 UPDATE + `SQL%ROWCOUNT` 检查——每个工单恰好被一个实例升级/通知一次。双会话竞态验证脚本见 [test_escalation_race_*.sql](../../database/sp/test_escalation_race_setup.sql)。
- **通知投递失败不升级为 500**：升级标记已由 SP 原子提交，端点若因通知失败返回 500，调度方重试也扫不到该工单（`Escalation_Time` 已非空）→ 提醒永久丢失。因此 `SlaDispatchService` 对每条通知投递失败记录 `LogError`（含工单号/房间/楼长），端点仍返回本次升级清单；develop 基线上的 ORA-01400 属通知模块缺口（见 §0 #4），难点④ 合入后投递即通。
