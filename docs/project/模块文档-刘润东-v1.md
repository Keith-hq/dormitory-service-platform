## 三、关键设计

1. **退宿状态机**（DORM-36/37/38）：待清算 →（校验失败）已拒绝 /（确认）已通过 /（取消）已取消。DB CHECK 约束仅允许这 4 个值；查询响应把"已通过"统一映射为对外契约终态"已清算"（8/14 联调与前端确认的取数口径）。
2. **三步校验（难点⑥）**：水电费缴清（D_Fee_Detail，排除 Bill_Type='退宿'）+ 快递全取走（D_Parcel_Record）+ 共享物品全归还（D_Item_Loan）。三个数据源均为**只读**，不写他人表；结算金额唯一来源为 SP_Calc_Checkout_Fee（IFeeSharingService 调用，v1.3 过程内不 COMMIT、同事务统一提交）。
3. **主键序列化（迁移 023）**：三张表主键（D_Bed_Allocation/D_Checkout_Log/D_Leave_Application）由序列 + 触发器生成（WHEN NEW IS NULL），EF 侧 ValueGeneratedOnAdd；移除 MAX+1 与 DbSaveRetry 重试。
4. **并发与幂等**：
   - DORM-06：进程内幂等缓存 + UK_D_ROOM_BUILDING_NO（楼栋级）数据库兜底，冲突号归入"已存在跳过"（OracleConstraintParser 解析 ORA-00001 约束名，重试上限 3，单调收敛）；
   - DORM-08/11：UK_D_BED_ALLOC_ACTIVE / UK_D_CHECKOUT_ACTIVE 兜底并发，命中转 409；
   - DORM-37：Status 并发令牌，并发 confirm 仅一个生效，另一请求按幂等返回；
   - IT-C10-004：settle 幂等（已通过的单重复清算不重复调 calc）。
5. **清算通知（IT-C2-001 ⑥）**：confirm 状态迁移成功后经公共服务 INotificationService 投递学生通知（数据拥有者边界，与 SlaDispatchService 同模式；业务性失败不阻断确认）。
6. **跨模块红线**：审计留痕（D_Audit_Event）须走审计公共服务（IAuditService.LogEventAsync），不直接落表。取消清算（IT-C2-005 ③）已接入：状态迁移成功后记录 CHECKOUT_CANCEL（目标 D_CHECKOUT_LOG/LogId、操作人账户），与业务变更共用同一 DbContext 原子提交；幂等重放不重复留痕。
7. **鉴权与归属校验（8/16 鉴权整改 + 8/17 评审整改）**：全模块 21 接口补齐 [Authorize]。学生自助侧（入住 POST /api/allocations、退宿清算 5、离校 STU-15/16/17/40）任意登录角色；宿管侧（房间 5、调寝、住户、楼栋 6、COUN-01~04）DormAdmin 策略（admin/super_admin）。系统无辅导员角色，COUN 审批由宿管代执行（C2 清单口径⑧）；楼栋 GET 收 DormAdmin 后 IT-C1-001（学生 token → 403）成立。
   **归属校验（评审阻塞 1 整改）**：学生自助接口从 JWT 解析当前学生（WalletController.ResolveStudentId 同范式，服务层 `accountId → StudentId`），操作他人资源一律 403；宿管（admin/super_admin）经控制器角色判定**显式放行**代办，不放行其他登录角色。归属校验置于资源加载之后、状态机校验之前，跨账号访问恒定 403、不泄露资源状态。
8. **楼栋删除外键兜底（IT-C10-002 ②）**：DeleteAsync 先业务预检（楼栋下有房间 → 400 提示），数据库外键冲突（ORA-02292）经 OracleConstraintParser.IsForeignKeyViolation 兜底翻译为 400，不再裸抛 500。
