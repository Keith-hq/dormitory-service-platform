## 二、造数方案

学生账号优先走 AUTH-04（同时创建登录账户，学生侧接口需要 token）；房间与业务数据 SQL 直插（IMPORT-01 批量导入、快递 #52 均未合入，批量初始化生成的 Room_ID 为序列值、不可控，无法满足用例硬编码 roomId=900101）。

```sql
-- 楼栋与房间（列名以真库迁移 016/023 DDL 为准核对）
INSERT INTO D_Building (Building_ID, Building_Name, Building_Type, Floor_Count)
VALUES (9, '九号楼', '男生宿舍', 6);

-- 900101：IT-C2-001 入住（bedNo 1），初始 Occupancy=0
INSERT INTO D_Room (Room_ID, Building_ID, Room_Number, Floor, Capacity, Occupancy, Status, Power_Status)
VALUES (900101, 9, '101', 1, 4, 0, '正常', '正常');
-- 900102：IT-C2-002 并发抢占，仅剩 bedNo 2（Occupancy=3 + 3 条在住分配占 bedNo 1/3/4）
INSERT INTO D_Room (Room_ID, Building_ID, Room_Number, Floor, Capacity, Occupancy, Status, Power_Status)
VALUES (900102, 9, '102', 1, 4, 3, '正常', '正常');
-- 900201：IT-C2-006 调寝目标（bedNo 1 空）
INSERT INTO D_Room (Room_ID, Building_ID, Room_Number, Floor, Capacity, Occupancy, Status, Power_Status)
VALUES (900201, 9, '201', 2, 4, 0, '正常', '正常');

-- IT-C2-003：IT_STU_003 未结月度账单（settle 欠费阻断）
INSERT INTO D_Fee_Detail (Detail_ID, Fee_ID, Student_ID, Bill_Type, Is_Paid, ...)
VALUES (..., 'IT_STU_003', '月度', '否', ...);

-- IT-C2-004：IT_STU_004 未取快递（Pickup_Time 为空）
INSERT INTO D_Parcel_Record (Parcel_ID, Student_ID, Arrive_Time, Pickup_Time)
VALUES (..., 'IT_STU_004', SYSDATE, NULL);
```

执行注意：
- C2-001 前置写的"有未结水电账单"按**退宿结算单（Bill_Type='退宿'，calc 生成待缴）**理解——该类型按实现口径不阻断清算；若给 IT_STU_001 造了未缴的**月度**账单，settle 会拒绝，与 happy path 冲突（欠费阻断是 C2-003 的职责）。
- 900102 的 3 条在住分配用假学生号（如 IT_HOLD_1~3）直插 D_Bed_Allocation，避免污染 IT_STU_001/002。
- **鉴权已补齐（8/16 整改批次）**：C2 全部接口需带 token，无 token 一律 401。学生侧（入住 / 退宿清算 5 接口 / STU-15,16,17,40）用学生 token；宿管侧（COUN-01~04 / 房间 / 楼栋 / 调寝 / 住户）用 admin token。

## 三、用例执行步骤

### IT-C2-001 退宿清算全链路（P0）

| 步骤 | 请求 | 期望 | 判定 |
|------|------|------|------|
| 入住 | `POST /api/allocations` `{studentId:"IT_STU_001", roomId:900101, bedNo:1, checkInDate:"2026-08-01"}` | code=0，记 allocationId | ① |
| 退宿登记 | `POST /api/allocations/{allocationId}/checkout-register` `{reason:"毕业退宿", checkoutDate:"2026-08-12"}` | code=0，记 checkoutId | ① |
| 结算×2 | `POST /api/feesharing/calc-checkout?studentId=IT_STU_001&allocationId={id}` 连调两次 | 两次金额一致、不重复扣款 | ② |
| 开始清算 | `POST /api/checkouts/{checkoutId}/settle` | code=0，三步校验通过 | ① |
| 确认×2 | `POST /api/checkouts/{checkoutId}/confirm` `{checkoutDate:"2026-08-12"}` 再调一次 | 重复确认不报错 | ③ |
| 终态 | `GET /api/checkouts/{checkoutId}` | status=已清算 | ④ |
| DB | 查 D_Bed_Allocation / D_Room / D_Fee_Detail | 分配已退宿、900101 占用-1、无重复结算记录 | ⑤ |
| 通知 | 学生 token `GET /api/notifications` | 可见"退宿办理完成" | ⑥ |

### IT-C2-002 并发入住同一床位（P1）

- 前置：900102 仅剩 bedNo 2；IT_STU_001、IT_STU_002 两个学生 token。
- 并发 `POST /api/allocations`，body 同为 `{roomId:900102, bedNo:2, checkInDate:"2026-08-01"}`（studentId 缺省时从登录态解析）。
- 期望：仅 1 人 code=0，另一人"床位已占用"（UK_D_BED_ALLOC_ACTIVE 兜底）；DB 该床位仅 1 条有效分配、占用数 +1（判定①②③）。
- 执行方式：Apifox 并发组 / 两脚本同时发。

### IT-C2-003 欠费阻断退宿（P1）

- 前置：IT_STU_003 有未结月度账单（造数 SQL）。
- 链：`GET /api/students/{studentId}/fees` → register → calc → `POST /api/checkouts/{checkoutId}/settle`。
- 期望：settle 返回 400"清算未通过：水电费未缴清"（判定①②）；DB 该清算记录状态=已拒绝、无脏数据（判定③，口径②）。

### IT-C2-004 物品未清校验（P1）

- 前置：IT_STU_004 有未取快递（造数 SQL）。
- 链：`GET /api/students/{studentId}/packages` → register → settle。
- 期望：settle 返回未通过项**逐项列出**（快递；若同时造欠费则水电+快递并列）（判定①）；状态落库=已拒绝、不可 confirm（判定②，口径①）；DB FeeCheck/ItemCheck 与快递表状态一致（判定③）。

### IT-C2-005 取消清算回滚（P1）

- 前置：已登记未确认的清算单（register + settle 通过）。
- 链：`POST /api/checkouts/{checkoutId}/cancel` → `GET /api/checkouts/{checkoutId}` → 房间占用查询。
- 期望：cancel code=0、状态=已取消（判定①）；DB 分配 Check_Out_Date 恢复 NULL、可重新发起退宿（判定②）；审计留痕（判定③，口径③）。

### IT-C2-006 调寝原子性（P1）

- 前置：IT_STU_001 在 900101；900201 bedNo 1 空。
- `POST /api/allocations/{allocationId}/transfer` `{targetRoomId:900201, targetBedNo:1}`。
- 期望：code=0；900101 占用-1、900201 占用+1 同一事务；DB 分配记录迁址正确、旧床位释放（判定①②）；并发同学生仅一次生效（判定③）。

### IT-C2-007 退宿后离校报备审批链路（P2）

| 步骤 | 请求 | 期望 | 判定 |
|------|------|------|------|
| 提交报备 | 学生 token `POST /api/leave-applications`（Apifox 契约：leaveDate/returnDate/destination 等） | code=0，记 applyId | — |
| 学生可见 | 学生 token `GET /api/students/{studentId}/leave-applications` | 可见且状态=待批 | ① |
| 辅导员列表 | 宿管 admin token `GET /api/leave-applications`（口径⑧） | 列表可见 | ② |
| 待批可改可撤 | `PUT /api/leave-applications/{applyId}`（STU-17）/ `POST /api/leave-applications/{applyId}/cancel`（STU-40） | 待批可用；审批后调用返回业务错误 | ② |
| 通过/驳回 | 宿管 admin token `PUT /api/leave-applications/{applyId}/approve` / `.../reject`（驳回必填原因）（口径⑧） | 状态=已通过 / 已驳回 | ③ |
| 统计 | `GET /api/leave-applications/stats` | 与审批结果一致 | ④ |
| DB | 查 D_Leave_Application | 状态与审批记录一致（"写操作人"见口径⑤） | ⑤ |

### IT-C10-004 分摊结算入口不重复（P2）

- 链：`POST /api/feesharing/calc-checkout` ×2 → 走 C2-001 的 register + settle。
- 期望：calc 两次金额一致（settle 内部再调 calc 仍一致、不重复扣款）；DB 无重复结算记录（判定①②③）。
- 注意：与李昂的 SP 防重（UK_D_FEE_DETAIL）联动，结算记录以 D_Fee_Detail 为准取证。
