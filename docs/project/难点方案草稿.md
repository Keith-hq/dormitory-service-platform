## 二、难点① 水电分摊

### 问题描述

财务按房间录入水电总额，但每人入住时长不同，需要公平分摊到个人。当前只有房间级账单，缺个人级账单。

### 解决方法

**人天数比例分摊算法**：某人应付 = 房间总额 × (该人入住天数 ÷ 房间总人天数)。总人天数 = 该房间所有在住学生每人当月入住天数之和。所有个人分摊加起来恰好等于房间总额。

### 触发时机及数据变动

**触发A — 每月1日：**
- 读取 D_Bed_Allocation 计算每位在住学生的当月入住天数
- 按比例算出 Water_Share 和 Power_Share
- 向 D_Fee_Detail 批量插入分摊记录，Bill_Type='月度'

**触发B — 学生退宿时（由难点⑥调用）：**
- 计算该学生本月1日至退宿日的入住天数
- 重新统计房间本月当前总人天数
- 向 D_Fee_Detail 插入分摊记录，Bill_Type='退宿'
- D_Bed_Allocation 写入 CheckOut_Date
- D_Room.Occupancy − 1

### 涉及的表

读取：D_Bed_Allocation、D_Utility_Fee、D_Room ｜ 写入：D_Fee_Detail（新表）、D_Bed_Allocation（退宿时）｜ 更新：D_Room.Occupancy（退宿时）

## 三、难点② 账单划扣与断电判定

### 问题描述

难点①已生成个人账单，但缺少自动扣费和逾期断电两个机制。

### 解决方法

**自动划扣**：每月1日分摊完成后立即扣款。遍历 D_Fee_Detail 账单，检查 D_Student.Balance：余额≥应付 → 扣减Balance、Is_Paid改为"是"；余额不足 → 一分不扣、Is_Paid保持"否"。学生充值后自动补扣未缴账单。

**断电判定**：当月15日0:00后，房间内存在任意 Is_Paid='否' → D_Room.Power_Status 置为"断电"。断电断整个房间。该房间全员缴清后自动恢复供电。

### 触发时机及数据变动

- **触发A — 每月1日（紧接难点①分摊后）：** Pay_Deadline=当月8日 → 遍历扣款 → 推送通知
- **触发B — 学生充值后：** Balance增加 → 补扣未缴账单 → 检查是否全员缴清（是则恢复供电）
- **触发C — 每日断电巡检（0:05）：** 扫描逾期未缴房间 → 断电

### 涉及的表

修改：D_Student（加Balance）、D_Room（加Power_Status）｜ 新增字段：D_Fee_Detail.Pay_Deadline

## 四、难点③ 洗衣机/浴室防冲突预约

### 问题描述

两人同时预约同一台洗衣机或同一间浴室的同一时段，不加锁会导致时段被双重占用。

### 解决方法

**时段重叠判断算法**：新预约的开始时间 < 已有预约的结束时间 AND 新预约的结束时间 > 已有预约的开始时间 → 冲突。

**加锁流程**：开启事务 → 对该设施所有未来时段行执行 SELECT FOR UPDATE → 逐条检查与新时段是否重叠 → 无重叠则INSERT → COMMIT。有重叠则ROLLBACK并提示冲突。

### 触发时机及数据变动

用户预约时实时触发。预约时间到了自动转"使用中"，超时15分钟未到自动取消释放时段。

### 涉及的表

D_Facility_Booking（新表，本方案设计）。目标行锁定：SELECT FOR UPDATE 锁定该设施所有未来时段行。

## 五、难点④ 库存联动事务

### 问题描述

订水、维修消耗配件、共享物品借还等操作需要同时修改多张表，两步必须一起成功或一起失败。

### 解决方法

6个跨表事务场景，全部遵循"锁行→校验→写表A→写表B→COMMIT（或ROLLBACK）"模式：

| 场景 | 操作 | 涉及表 |
|---|---|---|
| A 订水 | 扣库存+写订单 | D_Shared_Item + D_Water_Order |
| B 维修消耗 | 扣配件+写维修日志+改工单状态 | D_Asset + D_Repair_Log + D_Repair_Ticket |
| C 借出 | 改 Available_Qty −1 + 写借出记录 | D_Shared_Item + D_Item_Loan |
| D 归还 | 改 Available_Qty +1 + 写归还时间 | D_Shared_Item + D_Item_Loan |
| E 入住 | 插分配记录+Occupancy+1 | D_Bed_Allocation + D_Room |
| F 退宿 | 写退宿日期+Occupancy−1 | D_Bed_Allocation + D_Room |

桶装水库存复用 D_Shared_Item（Item_Name='桶装水'，Available_Qty=当前库存）。库存不足时通知楼长采购补货。

### 触发时机及数据变动

全部由用户操作实时触发。事务失败 → ROLLBACK → 返回具体失败原因。

### 涉及的表

复用：D_Water_Order、D_Repair_Log、D_Repair_Ticket、D_Bed_Allocation、D_Room。新建：D_Shared_Item（桶装水库存 + 共享物品）、D_Item_Loan（借还流水）。场景B维修消耗配件仍用 D_Asset。

## 六、难点⑤ SLA 派单

### 问题描述

报修工单需自动派给对应楼栋楼长，楼长超时未处理则自动升级并改派更高级别管理员。

### 解决方法

| 等级 | 时限 | 超时动作 | 指派对象 |
|---|---|---|---|
| 普通 | 24小时 | 升级为"紧急" | 楼长 |
| 紧急 | 12小时 | 升级为"特急" | 超级管理员 |
| 特急 | —（最高级） | 持续通知超管 | 全体超管 |

Quartz 定时任务每15分钟扫描 Status≠'已完成' AND NOW>Deadline 的工单，按等级规则升级。

### 触发时机及数据变动

- **触发A — 学生提交报修：** 自动查楼栋→楼长→设为Assigned_To，SLA_Level='普通'，Deadline=Submit_Time+24h
- **触发B — Quartz每15分钟巡检：** 扫描超时工单→升级等级→改派→重置Deadline
- **触发C — 管理员处理完成：** Status='已完成' + 写入D_Repair_Log

### 涉及的表

修改：D_Repair_Ticket（加SLA_Level、Deadline、Assigned_To）、D_Admin（加Building_ID）。Building_ID用于建立"楼长→楼栋"映射。

## 七、难点⑥ 退宿清算

### 问题描述

学生退宿前需通过5步校验，全部通过才执行退宿事务。本难点汇聚①②③④⑤的全部输出。

### 解决方法

**五步校验（串行，任一步失败即拒绝）：**

| # | 校验项 | 数据来源 | 判定规则 |
|---|---|---|---|
| ① | 水电费缴清 | D_Fee_Detail | Is_Paid='否'的记录=0 |
| ② | 快递全取走 | D_Parcel_Record | Pickup_Time IS NULL的记录=0 |
| ③ | 共享物品全归还 | D_Item_Loan | Return_Time IS NULL的记录=0 |
| ④ | 报修全完成 | D_Repair_Ticket | Status≠'已完成'的记录=0 |
| ⑤ | 违规记录处理 | D_Violation_Record | 有违规记录→调信用分服务扣分（不阻止退宿） |

**退宿事务（校验全部通过后）：** 锁D_Room行 → 调用难点①退宿分摊 → 写CheckOut_Date → Occupancy−1 → 调信用分服务 → 写D_Checkout_Log → COMMIT

### 触发时机及数据变动

学生发起退宿申请时实时触发。全部校验通过→执行退宿事务。任一不通过→写入D_Checkout_Log(Status='拒绝')，返回拒绝原因。

### 涉及的表

新建：D_Checkout_Log。读取：D_Fee_Detail、D_Parcel_Record、D_Repair_Ticket、D_Violation_Record。写入：D_Bed_Allocation.CheckOut_Date、D_Room.Occupancy−1。外部调用：架构师信用分服务。
