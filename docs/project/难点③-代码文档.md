## 一、架构概览

### 业务流程

```
学生点"立即使用"
  → SP_Book_Facility  → 检查设施状态/信用分/重复预约 → INSERT Status='已预约'
  → 15分钟内
    点"开始" → SP_Start_Use → Status='使用中', End_Time=+60min（预填）
    ↓
  提前结束 → SP_End_Use → Status='已完成', End_Time=实际时间
  自动到期 → SP_Auto_Complete → Status='已完成'
  → 15分钟未开始
    SP_Expire_Booking → Status='已失效'

Quartz 每15秒:
  SP_Expire_Booking   — 扫"已预约"超15分钟 → 失效
  SP_Auto_Complete    — 扫"使用中"超 End_Time → 完成
```

### 并发保护（双层）

| 层 | 机制 | 说明 |
|---|---|---|
| 应用层 | UK_D_FACILITY_BOOK_ACTIVE 函数索引 | 同一设施最多一条活跃预约（数据库级兜底） |
| 业务层 | 信用分检查 + 重复预约检查 | 学生端前置拦截 |

## 二、数据库层

### 2.1 依赖的表

| 表 | 角色 | 关键字段 |
|---|---|---|
| D_Facility | 读取 | Facility_ID PK, Facility_Code UNIQUE, Facility_Type, Status(正常/维修/停用) |
| D_Facility_Booking | 写入+更新 | Booking_ID PK, Facility_ID FK, Student_ID FK, Create_Time, Start_Time, End_Time, Status(已预约/使用中/已完成/已失效) |
| D_Credit_Account | 读取 | Current_Score, 低于 60 冻结预约 |

### 2.2 存储过程

| 存储过程 | 参数 | 返回 | 说明 |
|---|---|---|---|
| SP_Book_Facility | facilityId, studentId | OUT resultCode(0/1/2/3) | 预约设施 |
| SP_Start_Use | bookingId, studentId | OUT resultCode(0/1/2) | 开始使用 |
| SP_End_Use | bookingId, studentId | OUT resultCode(0/1/2) | 结束使用 |
| SP_Expire_Booking | — | — | 过期巡检 |
| SP_Auto_Complete | — | — | 超时自动完成 |

**SP_Book_Facility 流程**：

1. 检查 D_Facility.Status ≠ '正常' → rc=1
2. 检查 D_Credit_Account.Current_Score < 60 → rc=2
3. 检查该学生已有活跃预约 → rc=3
4. INSERT D_Facility_Booking（Status='已预约'，Start_Time/End_Time=NULL）

**SP_Start_Use**：身份校验 → 状态校验 → UPDATE，同时设 Start_Time=SYSDATE、End_Time=SYSDATE+60分钟（满足 CK_D_FACILITY_BOOK_TIME 约束）。

**SP_End_Use**：CASE WHEN SYSDATE>Start_Time THEN SYSDATE ELSE Start_Time+1秒（安全兜底）。

**文件**：`Services/IFacilityBookingService.cs`

```csharp
public interface IFacilityBookingService
{
    Task<int> BookFacility(int facilityId, string studentId);
    Task<int> StartUse(int bookingId, string studentId);
    Task<int> EndUse(int bookingId, string studentId);
    Task ExpireBookings();
    Task AutoComplete();
}
```
