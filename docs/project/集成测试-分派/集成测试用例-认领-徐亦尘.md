## 0. 契约口径（判定标准的地基）

| 项 | 约定 |
|---|---|
| 统一响应 | `{ code, message, data }`；**code=0/200 成功**，非 0 为业务错误码 |
| 分页 | 参数 `page/pageSize`，返回 `{ items, total, page, pageSize }` |
| 鉴权 | 登录 `POST /auth/login` 拿 token，后续接口带 `Authorization: Bearer <token>` |
| 幂等 | **`Idempotency-Key` 请求头**（契约显式标注）：STU-05 缴费、STU-07 充值、STU-25 借用、DORM-29 耗材出库 |
| data 未展开 | 多数 POST 的 `data` 契约未定义 → **成功以 code=0/200 判定，业务结果用后续 GET + DB 断言验证** |
| 遗留双路径 | `/api/notices`、`/api/buildings`、`/api/facilities`、`/api/feesharing/*` 为遗留接口，前端统一走编号接口 |

**测试数据预留**（同一开发库，避免撞车）：

| 资源 | 预留值 |
|---|---|
| 学生 studentId | IT_STU_001、IT_STU_002…（新开通用 IT_STU_005） |
| 宿管/辅导员 adminId | IT_ADMIN_001 / IT_COUN_001 |
| 导入模板 | 20 行学生.xlsx（含 1 行缺必填字段作失败样本） |

> ⚠️ operationId 后缀约定：`SUPER-01/02/03`（`-create/-delete/-list/-update`）、`SUPER-03`（`-create/-list/-update`）——本文用裸编号简称，**执行时以 Apifox 契约的 operationId 为准**。

### 4.1 C1 认证与权限（P0 · 你）

#### IT-C1-001 各角色登录 / 锁定与验证码 ｜ FP1-1 ｜ P0 ｜ 执行:＿＿ ｜ 结果:＿＿
**场景**: 四角色登录是否各归各工作台；错误密码与锁定机制是否生效。
**接口链**: `GET /auth/captcha` → `POST /auth/login` `{loginName, password}`
**前置与测试数据**: 学生 IT_STU_001、宿管 IT_ADMIN_001、辅导员 IT_COUN_001、超管各一，密码已知。
**数据样本**:
```
【登录】POST /auth/login   { "loginName":"IT_STU_001", "password":"<初始密码>" }
→ 预期: code=0，data 含 token 与角色
【错密码×5】重复 POST /auth/login（错误密码）
→ 预期: code≠0、message 可读；第 5 次后触发锁定并强制验证码
【带验证码】GET /auth/captcha → 再 POST /auth/login
→ 预期: 验证码通过后可登录
```
**通过判定**:
① 四角色均登录成功 code=0，且工作台与角色匹配；
② 错密码返回业务错误码（非 500）；
③ 连错 5 次锁定 + 必须验证码，锁定状态落库；
④ DB: 审计表有登录行为记录（含失败尝试）。

#### IT-C1-002 角色访问控制矩阵（越权） ｜ FP1-1 ｜ P0 ｜ 执行:＿＿ ｜ 结果:＿＿
**场景**: 低权限角色访问高权限接口是否被拒。
**接口链**: `GET /buildings`（宿管 DORM-01）｜ `GET /students`（超管 SUPER-03）｜ `GET /reports/{type}`（超管 REPT-01）｜ `GET /admins/{adminId}/repair-tickets`
**前置与测试数据**: 学生 token、宿管 token、普通学生 token。
**数据样本**:
```
学生 token → GET /buildings      → 预期: 403, code≠0
学生 token → GET /students       → 预期: 403, code≠0
宿管 token → GET /reports/{type} → 预期: 403, code≠0
学生 token → GET /admins/IT_ADMIN_001/repair-tickets → 预期: 403, code≠0
```
**通过判定**:
① 越权一律 **403 且 code≠0**（非 500）；
② 全部返回统一结构 `{code,message,data}`；
③ 越权不泄露数据（响应不含业务内容）。

#### IT-C1-003 首登强制改密 / token 生命周期 ｜ FP1-1 ｜ P0 ｜ 执行:＿＿ ｜ 结果:＿＿
**场景**: 新账号首登改密、改密后旧 token 失效、退出后 token 不可复用。
**接口链**: `POST /accounts/students` → `POST /auth/login` → `PUT /auth/password` → `GET /auth/me` → `POST /auth/logout`
**前置与测试数据**: 新开通学生账号（AUTH-04 或 IMPORT 联动）。
**数据样本**:
```
【开通】POST /accounts/students { "studentId":"IT_STU_005", "initialPassword":"123456" }
【首登】POST /auth/login → 改密前调任一业务接口 → 预期: 被拦（强制改密）
【改密】PUT /auth/password { "oldPassword":"123456", "newPassword":"newPass@1" }
【验证】旧密码登录 → 预期: 失败；新密码登录 → 成功
【退出】POST /auth/logout → 复用旧 token 调 GET /auth/me → 预期: 401
```
**通过判定**:
① 首登未改密前业务接口被拦；
② 改密后旧密码登录失败、新密码成功；
③ 退出后旧 token 失效（401）；
④ DB: 密码非明文存储。

#### IT-C1-004 超管导入→档案→账号自动开通 ｜ FP1-2、FP5-1 ｜ P0 ｜ 执行:＿＿ ｜ 结果:＿＿
**场景**: Excel 导入学生 → 档案入库 → 账号自动开通 → 可登录。
**接口链**: `POST /students/import` `{file}`（multipart）→ `GET /students` → `POST /auth/login`
**前置与测试数据**: Excel 模板 20 行（含 1 行缺必填字段作失败样本）。
**数据样本**:
```
【导入】POST /students/import  file=<20行学生.xlsx>
→ 预期: code=0；返回成功数=19、失败数=1（带失败原因）
【核对】GET /students?page=1&pageSize=50 → 预期: 可查到导入学生
【登录】POST /auth/login { "loginName":"<导入学号>", "password":"<默认密码>" } → 预期: code=0
```
**通过判定**:
① 导入成功数=有效行数，失败行有原因、**不整批回滚**；
② `GET /students` 可查；学院-专业-学生三级联动正确；
③ 学生账号自动开通可登录（若实现为手动开通，调 AUTH-04 后仍须满足本条）；
④ DB: 学生表与账号表一一对应。
