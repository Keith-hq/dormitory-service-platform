## 0. 契约口径（判定标准的地基）

| 项 | 约定 |
|---|---|
| 统一响应 | `{ code, message, data }`；**code=0/200 成功**，非 0 为业务错误码 |
| 分页 | 参数 `page/pageSize`，返回 `{ items, total, page, pageSize }` |
| 鉴权 | 登录 `POST /auth/login` 拿 token，后续接口带 `Authorization: Bearer <token>` |
| 幂等 | **`Idempotency-Key` 请求头**（契约显式标注）：STU-05 缴费、STU-07 充值、STU-25 借用、DORM-29 耗材出库 |
| data 未展开 | 多数 POST 的 `data` 契约未定义 → **成功以 code=0/200 判定，业务结果用后续 GET + DB 断言验证** |
| 退宿结算口径 | **settle 先写 CheckOut_Date，再调 calc（SP_Calc_Checkout_Fee）**；calc 无内部 COMMIT、由你退宿事务统一提交；同一退宿流程不重复触发结算；金额以李昂 calc 结果为准，不重复计算 |
| 遗留双路径 | `/api/buildings` 为遗留接口，前端统一走编号 DORM-01/02/03（IT-C10-002） |

**测试数据预留**（同一开发库，避免撞车）：

| 资源 | 预留值 |
|---|---|
| 楼栋 buildingId | 9001、9002 |
| 房间 roomId | 900101…900204（900101 房间仅剩 bedNo 2 用于并发） |
| 学生 studentId | IT_STU_001~004 |
| 宿管/辅导员 adminId | IT_ADMIN_001 / IT_COUN_001 |

> ⚠️ operationId 后缀约定：`DORM-01` 另有 `-detail`、`DORM-02`（`-create/-update`）——本文用裸编号简称，**执行时以 Apifox 契约的 operationId 为准**。

### 4.2 C2 退宿清算闭环（P0 · 你×李昂）— 你主执行流程侧

> 结算金额由李昂 calc-checkout 产出；IT-C2-001/003 中你跑流程侧、李昂跑结算侧。

#### IT-C2-001 退宿清算全链路（happy path + 幂等） ｜ FP3-16 ｜ P0 ｜ 执行:＿＿ ｜ 结果:＿＿
**场景**: 入住→退宿登记→结算→开始清算→确认退宿→释放床位→通知，全链路。
**接口链**: `POST /allocations` → `POST /allocations/{id}/checkout-register` → `POST /api/feesharing/calc-checkout?studentId=&allocationId=` → `GET /checkouts/{checkoutId}` → `POST /checkouts/{id}/settle` → `POST /checkouts/{id}/confirm` `{checkoutDate}`
**前置与测试数据**: IT_STU_001 入住 900101（bedNo 1）；有未结水电账单；分摊已产生（李昂侧）。
**数据样本**:
```
【入住】POST /allocations { "studentId":"IT_STU_001", "roomId":900101, "bedNo":1, "checkInDate":"2026-08-01" } → 记 allocationId
【退宿登记】POST /allocations/{allocationId}/checkout-register { "reason":"毕业退宿", "checkoutDate":"2026-08-12" } → 记 checkoutId
【结算×2】POST /api/feesharing/calc-checkout?studentId=IT_STU_001&allocationId={id}  → 连调两次，记录两次金额（李昂侧）
【开始清算】POST /checkouts/{checkoutId}/settle
【确认退宿×2】POST /checkouts/{checkoutId}/confirm { "checkoutDate":"2026-08-12" } → 再调一次
【终态】GET /checkouts/{checkoutId}
```
**通过判定**:
① 每步 code=0/200；
② **calc-checkout 连调两次金额一致、不重复扣款**（幂等，李昂侧）；
③ **confirm 重复执行不报错**（幂等）；
④ `GET /checkouts/{checkoutId}` 终态=已清算；
⑤ DB: `D_Allocation` 状态=已退宿、房间占用数-1；无重复结算记录；
⑥ 学生 `GET /notifications` 可见清算通知。

#### IT-C2-002 并发入住同一床位（唯一性） ｜ FP3-2 ｜ P1 ｜ 执行:＿＿ ｜ 结果:＿＿
**场景**: 最后一空床位被并发抢占时，只放行一人。

**前置与测试数据**: 房间 900102 仅剩 bedNo 2；IT_STU_001、IT_STU_002。

③ 无重复分配数据。

#### IT-C2-003 欠费阻断退宿 ｜ FP3-16 ｜ P1 ｜ 执行:＿＿ ｜ 结果:＿＿
**场景**: 有未结清账单时，退宿结算必须被拦。
**接口链**: `GET /students/{studentId}/fees` → `POST /allocations/{id}/checkout-register` → `POST /api/feesharing/calc-checkout` → `POST /checkouts/{id}/settle`
**前置与测试数据**: IT_STU_003 有未结账单（李昂侧提供）。
**通过判定**:
① 结算/清算返回欠费提示，code≠0；
② **不可进入清算**（结算未通过则 settle 拒绝）；
③ DB: 清算记录不产生或状态=阻塞，无脏数据。

#### IT-C2-004 物品未清校验（快递/借用） ｜ FP3-16 ｜ P1 ｜ 执行:＿＿ ｜ 结果:＿＿
**场景**: 有未取快递或未还借用时，开始清算被拦。
**接口链**: `GET /students/{studentId}/packages` → `POST /checkouts/{checkoutId}/settle`
**前置与测试数据**: IT_STU_004 有未取快递（对应 IT-C8-003 联动，王浩宇侧造数）。
**通过判定**:
① settle 返回未通过项提示（水电/快递/借用**逐项**列出）；
② 状态停在"清算中"，不继续；
③ DB: 校验项记录与快递/借用状态一致。

#### IT-C2-005 取消清算回滚 ｜ FP3-16 ｜ P1 ｜ 执行:＿＿ ｜ 结果:＿＿
**场景**: 清算可取消，且取消后床位与状态完整回滚。
**接口链**: `POST /checkouts/{checkoutId}/cancel` → `GET /checkouts/{checkoutId}` → 房间占用查询
**前置与测试数据**: 已退宿登记未确认的清算单。
**通过判定**:
① cancel 后 code=0，`GET /checkouts/{checkoutId}` 状态=已取消；
② DB: 原床位分配恢复占用，可重新发起退宿；无残留清算数据；
③ 取消动作写审计日志。

#### IT-C2-006 调寝原子性（旧房-1 新房+1） ｜ FP3-2 ｜ P1 ｜ 执行:＿＿ ｜ 结果:＿＿
**场景**: 调寝时新旧房间占用数在同一事务内增减，不出现不一致。
**接口链**: `POST /allocations/{allocationId}/transfer` `{targetRoomId, targetBedNo}`
**前置与测试数据**: IT_STU_001 在 900101；目标 900201 有空位。
**数据样本**:
```
POST /allocations/{allocationId}/transfer { "targetRoomId":900201, "targetBedNo":1 }
→ 预期: code=0；900101 占用-1、900201 占用+1（同一事务）
```
**通过判定**:
① 两房间占用数同时正确变化，**任一步失败则两房均不变**；
② DB: `D_Allocation` 记录迁址正确、旧床位释放；
③ 并发调寝同一学生仅一次生效。
