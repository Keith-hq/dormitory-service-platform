## 0. 契约口径（判定标准的地基）

| 项 | 约定 |
|---|---|
| 统一响应 | `{ code, message, data }`；**code=0/200 成功**，非 0 为业务错误码 |
| 分页 | 参数 `page/pageSize`，返回 `{ items, total, page, pageSize }` |
| 鉴权 | 登录 `POST /auth/login` 拿 token，后续接口带 `Authorization: Bearer <token>` |
| 幂等 | **`Idempotency-Key` 请求头**（契约显式标注）：STU-05 缴费、STU-07 充值、STU-25 借用、DORM-29 耗材出库 |
| data 未展开 | 多数 POST 的 `data` 契约未定义 → **成功以 code=0/200 判定，业务结果用后续 GET + DB 断言验证** |

**测试数据预留**（同一开发库，避免撞车）：

| 资源 | 预留值 |
|---|---|
| 学生 studentId | IT_STU_001、IT_STU_002… |
| 房间 roomId | 900101…900204 |
| 访客授权 authId / 快递 packageId / 投票 voteId | 按 Apifox 契约补 |

## 1. 你主执行的用例

### 4.8 C8 安全社区（P2 · 你）

> 三条数据样本均需你按 Apifox 契约补。

#### IT-C8-001 访客二维码申请→过期→撤销 ｜ FP2-13、FP3-12 ｜ P2 ｜ 执行:＿＿ ｜ 结果:＿＿
**场景**: 访客二维码限时有效、过期失效、撤销即时失效。
**接口链**: `POST /visitor-authorizations` `{visitorName, startTime, endTime}` → `GET /visitor-authorizations/{authId}` → `POST /internal/scheduler/visitor-expire` → `POST /visitor-authorizations/{authId}/revoke` → `GET /students/{studentId}/visitor-authorizations`
**前置与测试数据**: 兰皓衍协办触发过期定时接口（SVC-SCHED-06）。
**通过判定**:
① 凭证限时有效、过期后不可用；撤销后即时失效；
② 访客进出记录与授权关联；DB: 授权状态正确。

#### IT-C8-002 房间投票一人一票 ｜ FP2-12 ｜ P2 ｜ 执行:＿＿ ｜ 结果:＿＿
**场景**: 房间投票一人一票，非本房间学生不可投。
**接口链**: `GET /rooms/{roomId}/votes` → `POST /room-votes` `{roomId, title, options}` → `POST /room-votes/{voteId}/responses` `{optionId}` → `GET /room-votes/{voteId}`
**通过判定**:
① **一人一票**，重复投返回业务错误；
② 统计与票数一致；非本房间学生不可投。

#### IT-C8-003 快递取件与退宿联动 ｜ FP2-6 ｜ P2 ｜ 执行:＿＿ ｜ 结果:＿＿
**场景**: 未取快递时退宿 settle 校验不通过；取件后校验通过。
**接口链**: `GET /students/{studentId}/packages` → `POST /packages/{packageId}/pickup` → 再走 IT-C2-004 校验
**前置与测试数据**: 给 IT_STU_004 造一条未取快递（刘润东 IT-C2-004 需要这条数据）。
**通过判定**:
① 取件后 status=已取、时间记录；
② **未取件时退宿 settle 校验不通过**（对应 IT-C2-004，刘润东侧）；
③ DB: 快递记录与退宿校验联动一致。
