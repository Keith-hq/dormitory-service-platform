## 二、拆分逻辑（为什么这样分）

按《接口认领.md》的**接口级归属**，把每条用例的「接口链」落在数据/接口的所有者上；跨人链路（C2/C4/C5/C9/C10）里真正需要两人协作的用例，**主执行人唯一**，配合方的责任以「联调协办」表给出（提供数据 / 提供接口 / 校验某条判定）。归属依据：

- **退宿清算**：流程（DORM-11/36/37/38）→ 刘润东；结算金额（calc-checkout / SP_Calc_Checkout_Fee）→ 李昂（难点⑥ 分工对齐）。
- **报修**：学生端报修（STU-08~12）→ 辛泓毅；宿管端派单/接单/日志（DORM-26~30）→ 李昂；损坏资产转报修（DORM-16）触发 → 刘鸿铭、工单落李昂。
- **设施/共享物品**：预约/借用/库存（STU-19~27）→ 李昂；设施/共享物品主数据（DORM-45~49）→ 刘鸿铭。
- **巡检报表**：卫生/保洁/晚归业务（DORM-31~34/39/40、STU-13/14）→ 辛泓毅；统计报表（REPT-01）→ 徐亦尘。
- **双路径**：公告/设施 → 刘鸿铭；楼栋 → 刘润东；分摊结算 → 李昂。
- **公共服务**（SVC-SCHED/NOTIFY/CREDIT/FILE）作为内部依赖，相关用例的调度/扣分/文件部分由兰皓衍协办。

## 五、执行规则（每人文档里都有，总则在此）

1. **认领 + 校核（执行前）**：把自己文档里每条用例的 `执行:` 填上名字；逐条核对「通过判定 / DB 断言 / 前置与测试数据」与自己的实现一致，不一致当场改（PM 只按契约写，实现细节以你为准）。
2. **数据样本**：C1/C2/C3（P0）与 C2/C4/C5（跨人）已由 PM 补好，照抄进 Apifox 即可；**C6–C11 由执行人按 Apifox 契约补**（对应文档已标注），补完才算该执行人闭环。
3. **执行时**：照用例跑，`通过判定` 全部满足才打「通过」；失败记 `失败+缺陷号`，缺陷进 bug 清单（字段见《集成测试用例-v1》§6.2）。
4. **闭环标准**：① 各人执行认领表确认 ② C6–C11 数据样本补齐 ③ 校核完成 ④ 全部执行完、P0 全绿、追踪矩阵填完。
5. **P0 红线**：C1/C2/C3 主线必须全绿才算「集成测试通过」；任一失败即阻塞云端正式部署（详见《集成测试用例-v1》§6.6）。
6. **判定标准以《集成测试用例-v1》为权威**：本分派文档只做执行拆分与归属，若两条口径冲突以 v1 为准；但你的「通过判定」实现细节以你为准（见第 1 条）。
