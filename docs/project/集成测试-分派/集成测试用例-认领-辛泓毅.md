## 0. 契约口径（判定标准的地基）

| 项 | 约定 |
|---|---|
| 统一响应 | `{ code, message, data }`；**code=0/200 成功**，非 0 为业务错误码 |
| 分页 | 参数 `page/pageSize`，返回 `{ items, total, page, pageSize }` |
| 鉴权 | 登录 `POST /auth/login` 拿 token，后续接口带 `Authorization: Bearer <token>` |
| 幂等 | **`Idempotency-Key` 请求头**（契约显式标注）：STU-05 缴费、STU-07 充值、STU-25 借用、DORM-29 耗材出库 |
| data 未展开 | 多数 POST 的 `data` 契约未定义 → **成功以 code=0/200 判定，业务结果用后续 GET + DB 断言验证** |

**测试数据预留**（同一开发库，避免撞车）：

| 资源 | 预留值 |
|---|---|
| 学生 studentId | IT_STU_001、IT_STU_002… |
| 房间 roomId | 900101…900204 |
| 报修工单 ticketId | 近期“待处理”工单、近期“已派单且无维修日志”工单、超过 10 分钟工单各 1 条 |
| 年月 yearMonth | 执行当天所在月份（`yyyy-MM`），不得写死历史月份 |

### 4.4 C4 报修 SLA 派单（P1 · 李昂×你）— 你主执行撤单/图片侧

> 数据样本需你按 Apifox 契约补；报修→派单主链路（001）由李昂主跑、你协办学生端。

#### IT-C4-004 撤销工单与报修图片 ｜ FP2-5 ｜ P1 ｜ 执行:辛泓毅 ｜ 结果:＿＿
**场景**: 报修图片可上传引用；撤销受状态机约束。
**接口链**: `POST /repair-tickets/{id}/attachments` `{files}` → `POST /repair-tickets/{id}/cancel`
**前置与测试数据**:
- 学生 IT_STU_001 已入住 roomId=900101，并能正常登录取得 student token。
- 新建近期工单：`POST /repair-tickets { "description":"宿舍洗手池水龙头持续漏水", "urgency":"普通", "roomId":900101 }`，记录 `ticketId`。
- 准备一张小于文件服务限制的 `repair-test.png`，以 multipart/form-data 的 `files` 字段上传。
- 另准备“已派单且无维修日志”的近期工单和“提交时间超过 10 分钟”的工单，用于撤销边界验证；撤销后不再派单由李昂协办确认。
**通过判定**:
① 图片走 SVC-FILE-01，`GET /internal/files/{ref}` 可访问（文件侧兰皓衍）；
② 提交后 10 分钟内，“待处理”或“已派单且无维修日志”均可撤销；超过 10 分钟拒绝撤销；
③ “已派单”且已有维修日志时拒绝撤销；不存在“待派单/处理中”状态；
④ 撤销后工单置“已撤销”、不再派单，并通过公共审计服务记录撤销事件。

### 4.9 C9 巡检 / 保洁 / 报表（P2 · 你×徐亦尘）— 你主执行卫生/晚归业务侧

> 数据样本需你按 Apifox 契约补；**IT-C9-002 保洁→报表由徐亦尘主跑，你协办保洁任务完成侧**（见第二节联调协办表）。

#### IT-C9-001 卫生打分→成绩→排名 ｜ FP2-9、FP3-14 ｜ P2 ｜ 执行:辛泓毅 ｜ 结果:＿＿
**接口链**: `POST /hygiene-records` `{roomId, score}` → `PUT /hygiene-records/{recordId}` `{score}` → `GET /rooms/{roomId}/hygiene` → `GET /hygiene-rankings?yearMonth=`
**前置与测试数据**:
- roomId=900101 存在且属于当前宿管负责楼栋；IT_STU_001 当前入住该房间。
- 宿管调用 `POST /hygiene-records { "roomId":900101, "score":92, "comment":"地面整洁，物品摆放规范" }`，记录 `recordId`。
- 24 小时内调用 `PUT /hygiene-records/{recordId} { "score":95, "comment":"复查通过" }`。
- 学生查询 `GET /rooms/900101/hygiene`；排名查询的 `yearMonth` 使用执行当天所在月份（`yyyy-MM`）。
**通过判定**:
① 成绩与学生可见一致；修改有操作人/时间；
② 评分仅允许在登记后 24 小时内修改，超时返回业务错误；
③ 排名计算正确、平均分达到 90 的房间进入文明寝室排名；DB: 评分记录一致。

#### IT-C9-003 晚归登记→补充说明 ｜ FP2-7、FP3-13 ｜ P2 ｜ 执行:辛泓毅 ｜ 结果:＿＿
**接口链**: `POST /late-entries` `{studentId, recordTime}` → `GET /students/{studentId}/late-entries` → `PUT /late-entries/{recordId}/reason` `{reason}`
**前置与测试数据**:
- IT_STU_001 存在且可登录；宿管使用 admin token 人工登记。
- `recordTime` 使用最近一个已经过去、且距当前不足 24 小时的 23:40，调用 `POST /late-entries { "studentId":"IT_STU_001", "recordTime":"<上述时间>" }`，记录 `recordId`。
- 学生调用 `GET /students/IT_STU_001/late-entries?page=1&pageSize=10`，再调用 `PUT /late-entries/{recordId}/reason { "reason":"公交末班车延误" }`。
- 另准备一条 `recordTime` 超过 24 小时的记录验证过期失败；23:30 前或晚于当前时间 5 分钟以上的登记应被拒绝。
**通过判定**:
① 登记后学生可见并可在时限内补说明；
② 仅允许登记 23:30 后且不晚于当前时间 5 分钟以上的记录；
③ 登记后 24 小时内可补说明，过期不可补（业务错误）；DB: 晚归记录与说明关联。
