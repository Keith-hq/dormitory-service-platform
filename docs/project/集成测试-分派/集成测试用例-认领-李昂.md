## 0. 契约口径（判定标准的地基）

| 项 | 约定 |
|---|---|
| 统一响应 | `{ code, message, data }`；**code=0/200 成功**，非 0 为业务错误码 |
| 分页 | 参数 `page/pageSize`，返回 `{ items, total, page, pageSize }` |
| 鉴权 | 登录 `POST /auth/login` 拿 token，后续接口带 `Authorization: Bearer <token>` |
| 幂等 | **`Idempotency-Key` 请求头**（契约显式标注）：STU-05 缴费、STU-07 充值、STU-25 借用、DORM-29 耗材出库 |
| data 未展开 | 多数 POST 的 `data` 契约未定义 → **成功以 code=0/200 判定，业务结果用后续 GET + DB 断言验证** |
| 遗留双路径 | `/api/feesharing/*`（含 calc-checkout）为遗留接口；**calc-checkout 与 DORM-36 职责边界已对齐**：结算归你（只读床位表、金额唯一来源）、流程归刘润东，不重复计算（IT-C10-004） |

**测试数据预留**（同一开发库，避免撞车）：

| 资源 | 预留值 |
|---|---|
| 楼栋 buildingId | 9001、9002 |
| 房间 roomId | 900101…900204 |
| 学生 studentId | IT_STU_001、IT_STU_002… |
| 年月 yearMonth | 2026-07 |
| Idempotency-Key | 每条用例独立，如 `IT-C3-001-1` |

> ⚠️ operationId 后缀约定：`DORM-14`/`DORM-43`/`DORM-49`（`-delete/-update`）——本文用裸编号简称，**执行时以 Apifox 契约的 operationId 为准**。

### 4.3 C3 缴费划扣链路（P0 · 你）

#### IT-C3-001 账单发布→分摊→缴费→断电判定/恢复 ｜ FP2-3、FP3-5/6/7 ｜ P0 ｜ 执行:＿＿ ｜ 结果:＿＿
**场景**: 录账单→发布→分摊→缴费→欠费断电/缴清恢复，全链路。
**接口链**: `POST /utility-fees` → `POST /utility-fees/{id}/publish` → `POST /utility-fees/{id}/allocate` → `POST /wallet/payments` `{detailId}`+`Idempotency-Key` → `GET /students/{id}/wallet` → `GET /rooms/{roomId}/power-status`
**前置与测试数据**: IT_STU_001 钱包余额不足；房间 900101。
**数据样本**:
```
【录账单】POST /utility-fees { "roomId":900101, "yearMonth":"2026-07", "waterFee":30.0, "elecFee":70.0 } → 记 feeId
【发布】POST /utility-fees/{feeId}/publish → 预期: code=0
【分摊】POST /utility-fees/{feeId}/allocate → 预期: code=0
【缴费】POST /wallet/payments { "detailId":<DORM-23明细的detailId> }  头: Idempotency-Key: IT-C3-001-1 → 预期: code=0
【断电】GET /rooms/900101/power-status → 预期: 欠费时=断
【充值缴费】POST /wallet/recharges { "amount":100 } + Idempotency-Key → 再缴费 → 预期: 成功
【恢复】GET /rooms/900101/power-status → 预期: 缴清后=正常
```
**通过判定**:
① 各步 code=0/200；
② **同 Idempotency-Key 重复缴费只扣一次**；
③ 欠费时 `GET /rooms/900101/power-status`=断，缴清后恢复；
④ DB: `D_Room.Power_Status` 与查询一致；账单 isPaid=已缴。
