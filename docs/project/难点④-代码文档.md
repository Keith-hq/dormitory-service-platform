## 〇、业务规则（组长确认）

> 三审要求：扣分额度和触发时机必须与组长确认，确认后统一 PRD、映射文档、实现和测试。

**超时归还扣 2 分、归还确认只扣一次**（按正式 PRD，组长确认）。

- **触发时机**：归还时（STU-26 归还成功且 `Due_Time < Return_Time`）。
- **额度**：固定按次扣 2 分，与逾期天数无关。
- **扣分入口**：统一走信用分公共服务 `ICreditService.DeductAsync`（难点②合并服务），
  - `Event_Key = OVERDUE-{Loan_ID}`：同一笔借出只扣一次（`UK_D_CREDIT_LOG_EVENT` 唯一约束兜底）；
  - 同一学生的扣分经 `D_STUDENT` 行锁（`SELECT ... FOR UPDATE WAIT 5`）串行化；
  - 跌破 60 分冻结线时由信用分服务统一发冻结通知（Notification_Type='信用'），语义不丢失。
- **逾期巡检不再扣分**：逾期巡检只给借款人发逾期提醒（'系统' 通知，同笔借出同日一条，
  四审起由应用层 OverdueCheckJob 走通知公共服务，见 §〇-2 / §五），
  由此"归还 × 巡检并发"的扣分写方只有一个（归还路径），配合 Event_Key 幂等，只产生一次目标扣分。

## 〇-2、四审修订总览（2026-08-13）

> 四审结论：三审第 2、3 项已闭环；本版修复 3 个阻塞问题并完成真实 Oracle 验证。

**P1-1 「是否逾期」与「展示天数」分离（刚逾期不足 24 小时也要扣分）**

- `SP_Return_Item` 输出拆分为 `p_Is_Overdue`（`Return_Time > Due_Time` 即逾期，决定扣分）
  与 `p_Overdue_Days`（展示用，`GREATEST(1, TRUNC(...))` 至少 1 天）。
- 边界测试（真实 Oracle）：刚超时 1 秒、1 小时均 `Is_Overdue=1` 且展示天数=1；未到期为 0/0。

**P1-2 归还提交后信用扣分失败 → 补偿闭环（不再留永久不一致）**

- `CreditDeductDto.FloorAtZero`：信用服务在 `D_STUDENT` 行锁内按当前分数封底到 0，
  低分学生（如 1 分）不再因「结果低于 0」被拒；流水记录名义分值 `-2`，幂等内容比对一致。
- `ReturnItem` 返回 `(ResultCode, CreditPending)`：归还已提交但扣分失败时
  `creditPending=true` 并提示「系统将自动重试」，**归还成功语义不因扣分失败而丢失**。
- `OverdueCheckJob` 自愈巡检：扫描「已归还逾期、无 `OVERDUE-{Loan_ID}` 流水」的借出
  逐笔重试扣分（Event_Key 幂等兜底，已扣的不重复）；账户停用（40401）跳过不再重试。
  **五审撤销**：`FloorAtZero` 封底随公共服务还原 develop 版移除（见 §〇-3 阻塞2），
  相关「分数=1 → 0」验证不再适用，待架构负责人确认后以独立 PR 恢复。
- 真实验证：扣分失败后巡检补扣挂起借出且二轮运行零新增（幂等）。

**P1-3 逾期提醒改走通知公共服务（原 SP 绕过公共服务、MAX+1 主键、COUNT+INSERT 去重并发不安全）**

- `SP_Check_Overdue` 已删除；`OverdueCheckJob`（C#）读取逾期候选后调用公共
  `INotificationService.CreateAsync`。
- 并发唯一语义：每笔借出先 `SELECT ... FOR UPDATE` 行锁互斥，锁内「同日已提醒」
  检查与插入同事务完成——不再依赖 COUNT+INSERT。
- 通知主键：五审起回归基线触发器 `TRG_D_NOTIFICATION_ID_BI` 生成
  （`SEQ_NOTIFICATION.NEXTVAL` 应用层预取已撤销，见 §〇-3 阻塞1），不再 MAX+1。

## 一、架构概览

### 业务流程

```
学生端（STU-24~27）
  │
  ├─ GET  /api/shared-items                       → 查询可借物品（状态=正常 + 库存>0）
  ├─ POST /api/item-loans  (Idempotency-Key 必填)
  │     → SP_Borrow_Item → 幂等/内容比对 → 信用分≥60？→ 原子扣库存(Available_Qty-1) → 写借出记录(期24h)
  │     → 返回 (rc, loanId)
  │
  ├─ POST /api/item-loans/{loanId}/return
  │     → SP_Return_Item → 原子写归还时间(校验归属) → 库存+1 → 返回逾期天数
  │     → 超期？→ ICreditService.DeductAsync(-2, Event_Key=OVERDUE-{loanId})  ← 统一扣分入口
  │
  └─ GET  /api/students/{studentId}/item-loans?page=&pageSize=
        → 本人校验(403) + 分页返回借还记录

宿管端（DORM-29~30）
  │
  ├─ GET  /api/repair-materials                    → 查询耗材库存
  └─ POST /api/repair-tickets/{ticketId}/materials (Idempotency-Key 必填)
        → SP_Consume_Material → 幂等/内容比对 → 原子扣库存(Stock_Qty-n) → 写消耗记录

定时任务
  └─ 每15分钟: OverdueCheckJob → ① 扫逾期未归还 → 行锁互斥 + 同日去重 → 调通知公共服务发提醒（不扣分）
                               ② 自愈补扣：已归还逾期但无 OVERDUE-{Loan_ID} 流水 → 重试扣分（Event_Key 幂等）
```

### 并发保护与幂等

| 层 | 机制 | 说明 |
|---|---|---|
| 借出/出库 | `UPDATE WHERE Available_Qty > 0 / Stock_Qty >= n` + `SQL%ROWCOUNT` | 原子扣减，无需显式加锁 |
| 幂等快路径 | 同 `Idempotency_Key` 已存在 → 读取原记录并**比对完整请求内容** | 内容一致返回原结果；不一致返回业务错误码（借出 rc=5 / 出库 rc=3） |
| 并发重放 | 唯一索引 `UK_D_ITEM_LOAN_IDEM` / `UK_D_REPAIR_MAT_USE_IDEM` 兜底 | INSERT 撞唯一索引 → `ROLLBACK TO SAVEPOINT` 撤销库存扣减 → 重读胜者记录比对内容 → 返回原结果或冲突码 |
| 归还 | `UPDATE ... WHERE Return_Time IS NULL AND Student_ID = p_Student_ID` | 原子守门：同一 Loan_ID 只能归还一次，且防跨用户枚举 |
| 逾期扣分 | `Event_Key = OVERDUE-{Loan_ID}` + `UK_D_CREDIT_LOG_EVENT` + `D_STUDENT` 行锁 | 统一入口串行化，只扣一次 |
| 巡检提醒 | 每笔借出 `SELECT ... FOR UPDATE` 行锁互斥，锁内「同日已提醒」检查+插入同事务 | 同笔借出同日一条；通知走公共服务，不再 MAX+1/COUNT+INSERT |
| 自愈补扣 | Event_Key = `OVERDUE-{Loan_ID}` 幂等 + 近 7 天时间窗（五审） | 归还已提交但扣分失败的借出由巡检逐笔重试，最终一致 |

### 事务边界

```
共享物品库存（D_Shared_Item.Available_Qty）← 李昂（难点④ SP_Borrow_Item / SP_Return_Item）
共享物品主数据（D_Shared_Item.* 增删改）    ← 刘鸿铭（DORM-48/49）
                                          两者通过 SP 接口隔离，不直改对方数据
信用分（D_Credit_Account / D_Credit_Log）  ← 难点②信用分公共服务（唯一写方）
                                          难点④只读信用分做借出闸门、只通过
                                          ICreditService.DeductAsync 发起扣分
```

### 2.3 存储过程：SP_Borrow_Item

**功能**：幂等检查（含内容比对）→ 信用分闸门 → 原子扣库存并写借出记录；并发重放由唯一索引兜底。

**参数**：

| 参数 | 类型 | 说明 |
|---|---|---|
| p_Item_ID | NUMBER | 共享物品 ID |
| p_Student_ID | VARCHAR2 | 借出学生学号 |
| p_Idempotency_Key | VARCHAR2 | 幂等键（应用层强制必填） |
| p_Result_Code | OUT NUMBER | 0=成功, 1=物品不存在, 2=物品停用, 3=库存不足, 4=信用分不足（低于60）, 5=幂等键已使用且请求内容不一致, 6=幂等键超过 100 字符（五审起按迁移 019 CHAR 语义，LENGTH 判定）, 7=学生不存在（六审 P3-3：捕获 ORA-02291 FK_D_ITEM_LOAN_STUDENT，库存扣减随 SAVEPOINT 回滚） |
| p_Loan_ID | OUT NUMBER | 借出记录 ID（rc=0 时有效，幂等重放返回原 ID） |

**处理流程**：

0. 幂等键边界校验（五审）：`LENGTH(p_Idempotency_Key) > 100` → rc=6（列宽 VARCHAR2(100 CHAR)，迁移 019 CHAR 语义，避免 ORA-12899 冒泡成 500）
1. 幂等快路径：同 Key 已存在 → 比对 `Student_ID + Item_ID`
   - 一致 → rc=0 返回原 `Loan_ID`；不一致 → **rc=5**（明确业务错误）
2. Fail-fast 校验：物品存在？→ 状态=正常？→ 库存 > 0？→ 信用分 ≥ 60？（只读闸门，不扣分）
3. `SAVEPOINT sp_borrow` → `UPDATE ... SET Available_Qty = Available_Qty - 1 WHERE Available_Qty > 0`
4. `SQL%ROWCOUNT = 0` → rc=3
5. `INSERT D_Item_Loan`（Due_Time = SYSDATE + 1，24 小时后到期，写入 Idempotency_Key）
6. `DUP_VAL_ON_INDEX`（并发同 Key 重放）→ `ROLLBACK TO sp_borrow` 撤销库存扣减 →
   重读胜者记录（Oracle 保证唯一冲突可见时胜者已提交）→ 内容比对 → rc=0 返回原 ID 或 rc=5
7. `ORA-02291`（FK_D_ITEM_LOAN_STUDENT，六审 P3-3）→ `ROLLBACK TO sp_borrow` 撤销库存扣减 → **rc=7**
8. COMMIT

**信用分阈值**：Current_Score < 60 → 冻结，拒绝借出。阈值对齐 `D_Credit_Account` 的冻结线。

### 2.4 存储过程：SP_Return_Item

**功能**：原子写归还时间（校验归属）→ 库存 +1 → 输出「是否逾期」与「展示天数」。**不触碰信用分表。**

**参数**：

| 参数 | 类型 | 说明 |
|---|---|---|
| p_Loan_ID | NUMBER | 借出记录 ID |
| p_Student_ID | VARCHAR2 | 归还学生学号（跨用户归还拦截） |
| p_Result_Code | OUT NUMBER | 0=成功, 1=借出记录不存在/已归还/非本人 |
| p_Is_Overdue | OUT NUMBER | 是否逾期（四审 P1-1）：`SYSDATE > Due_Time` 即逾期，决定是否扣分 |
| p_Overdue_Days | OUT NUMBER | 展示用逾期天数（0=未逾期；逾期时至少为 1），**不参与扣分判定** |

**处理流程**：

1. `UPDATE D_Item_Loan SET Return_Time = SYSDATE WHERE Loan_ID = p_Loan_ID AND Return_Time IS NULL AND Student_ID = p_Student_ID`（原子守门）
2. `SQL%ROWCOUNT = 0` → rc=1
3. 库存回加：`UPDATE D_Shared_Item SET Available_Qty = Available_Qty + 1`
4. `SYSDATE > Due_Time` → `p_Is_Overdue = 1`，`p_Overdue_Days = GREATEST(1, TRUNC(SYSDATE - Due_Time))`
   （刚超时 1 秒 / 1 小时同样触发扣分、展示为 1 天）
5. COMMIT

**扣分位置**：应用层 `InventoryTxnService.ReturnItem` 在 SP 返回 rc=0 且 `p_Is_Overdue=1` 时，
调用 `ICreditService.DeductAsync`（ScoreChange=-2，Event_Key=`OVERDUE-{Loan_ID}`）。
扣分失败不改变归还成功语义（creditPending 标记 + 自愈巡检重试，见 §3.3 / §五）。

> 五审撤销：`FloorAtZero=true` 参数已随公共服务还原 develop 版一并移除（见 §〇-3 阻塞2）。

### 2.5 存储过程：SP_Consume_Material

**功能**：幂等检查（含内容比对）→ 原子扣耗材库存并写消耗记录；并发重放由唯一索引兜底。

**参数**：

| 参数 | 类型 | 说明 |
|---|---|---|
| p_Material_ID | NUMBER | 耗材 ID |
| p_Ticket_ID | NUMBER | 关联报修工单 ID |
| p_Quantity | NUMBER | 消耗数量 |
| p_Idempotency_Key | VARCHAR2 | 幂等键（应用层强制必填） |
| p_Result_Code | OUT NUMBER | 0=成功, 1=耗材不存在, 2=库存不足, 3=幂等键已使用且请求内容不一致, 4=幂等键超过 100 字符（五审起按迁移 019 CHAR 语义，LENGTH 判定）, 5=票单不存在（六审 P2-2：捕获 ORA-02291 FK_D_REPAIR_MAT_USE_TICKET，库存扣减随 SAVEPOINT 回滚） |

**处理流程**：

0. 幂等键边界校验（五审）：`LENGTH(p_Idempotency_Key) > 100` → rc=4（列宽 VARCHAR2(100 CHAR)，迁移 019 CHAR 语义，避免 ORA-12899 冒泡成 500）
1. 幂等快路径：同 Key 已存在 → 比对 `Ticket_ID + Material_ID + Quantity` → 一致 rc=0，不一致 **rc=3**
2. `SAVEPOINT sp_consume` → `UPDATE ... SET Stock_Qty = Stock_Qty - p_Quantity WHERE Stock_Qty >= p_Quantity`
3. `SQL%ROWCOUNT = 0` → 回查区分"不存在"(rc=1) / "不够"(rc=2)
4. `INSERT D_Repair_Material_Usage`（写入 Idempotency_Key）
5. `DUP_VAL_ON_INDEX` → `ROLLBACK TO sp_consume` → 重读胜者记录 → 内容比对 → rc=0 或 rc=3
6. `ORA-02291`（FK_D_REPAIR_MAT_USE_TICKET，六审 P2-2）→ `ROLLBACK TO sp_consume` 撤销库存扣减 → **rc=5**
7. COMMIT

### 2.6 逾期巡检（四审 P1-3：SP_Check_Overdue 已删除）

原 `SP_Check_Overdue` 绕过通知公共服务直写 `D_Notification`（MAX+1 主键 + COUNT+INSERT
去重，并发不安全），四审起删除。逾期提醒改由应用层 `OverdueCheckJob` 实现（见 §五）：

1. 读取逾期未归还候选（`Return_Time IS NULL AND Due_Time < SYSDATE`，账户状态=正常）
2. 每笔借出 `SELECT ... FOR UPDATE` 行锁互斥 → 锁内「同日已提醒」检查（Title + Content 内嵌 `Loan_ID` + 当日）→
   调公共 `INotificationService.CreateAsync` 插入（Notification_Type='系统'）——检查+插入同事务
3. 通知主键由基线触发器 `TRG_D_NOTIFICATION_ID_BI` 生成（五审起不再应用层预取），不再 MAX+1
4. 单个候选失败：业务/数据库类异常只记录、失败实体 Detach（五审建议），不影响其余候选与主业务；编程错误向上抛出令巡检 Job 失败（六审 P3-2 收窄，与补扣路径 catch 策略一致）；**巡检不扣分**（扣分只在归还路径）

### 3.3 服务实现

**文件**：`backend/Services/InventoryTxnService.cs`（注入 `AppDbContext` + `ICreditService`）

**写操作**：OUT 参数存储过程使用原生 `OracleCommand` 调用（`CommandType.StoredProcedure`），
处理 `OracleDecimal` → `int` 类型转换。

- `BorrowItem`：返回 `(rc, loanId)` 元组
- `ReturnItem`（四审 P1-2 / 五审修订）：
  1. 调 `SP_Return_Item` 得到 `(rc, isOverdue, overdueDays)`
  2. rc=0 且 `isOverdue=1` → `DeductOverdueAsync`：`DeductAsync(new CreditDeductDto { ScoreChange = -2,
     EventKey = $"OVERDUE-{loanId}", ... })`（五审：FloorAtZero 随公共服务还原移除）；
     仅账户停用（40401）与「分数低于罚分」的 400 拒绝（原封底才会出现，封底待架构负责人
     确认后独立 PR）按永久失败跳过，其余失败一律 `creditPending=true` 返回
     （归还成功语义不变，由自愈巡检重试）
  3. rc=1 补偿路径：本人 + 已归还 + 逾期 → 补发扣分（幂等，最多一次）
- `ConsumeMaterial`：返回 rc
- `CheckOverdue`：先发逾期提醒（行锁互斥 + 同日去重，失败实体 Detach），再
  `CompensatePendingDeductionsAsync` 自愈补扣（五审：只扫描**近 7 天归还**的逾期借出、
  无 `OVERDUE-{Loan_ID}` 流水者逐笔重试，Event_Key 幂等；catch 收窄为
  `BusinessException \| DbException`，编程错误向上抛出）

**查询操作**：`FromSqlRaw` 显式 SQL 别名映射；`GetItemLoans` 用 `SqlQueryRaw<int>`
（输出列显式 `AS "Value"`）统计总数，分页下推原生 `OFFSET {n} ROWS FETCH NEXT {m} ROWS ONLY`
且列别名全加引号（真实 Oracle 实测：Skip/Take 组合外层按模型列名引用 → ORA-00904；
无引号别名被 Oracle 大写化 → 列名不匹配），返回 `PagedResult<ItemLoan>`（Items/Total/Page/PageSize）。

### 3.4 信用分统一入口（关键）

扣分语义全部由难点②合并的信用分公共服务保证（已由 `CreditServiceTests` 单测覆盖）：

- 幂等：`Event_Key` 已存在 → 内容一致返回原结果；不一致抛 `BusinessException(400, "Event_Key 已存在且请求内容不一致")`
- 串行化：`D_STUDENT` 行锁（`SELECT ... FOR UPDATE WAIT 5`），同一学生扣分串行
- 冻结通知：分数从 ≥60 跌破 60 时发 '信用' 通知（`TryNotifyFreezeAsync`）
- 主键：五审起回归基线触发器 `TRG_D_CREDIT_LOG_ID_BI` 生成（`AssignLogKeyAsync` 预取已随
  公共服务还原 develop 版一并撤销；此前 ORA-01400 系测试库缺失迁移 012/014 的环境问题，
  补齐迁移后触发器路径实测通过）

## 五、定时任务

**文件**：`backend/Jobs/OverdueCheckJob.cs`

| Job | cron | 说明 |
|---|---|---|
| OverdueCheckJob | `0 0/15 * * * ?` | 每 15 分钟：① 逾期提醒（走通知公共服务）；② 自愈补扣（四审 P1-2） |

- `[DisallowConcurrentExecution]`：防止上次扫描未完成时再次触发
- 提醒去重：每笔借出行锁（`FOR UPDATE`）互斥，锁内检查+插入同事务，同笔借出同日一条
- 自愈补扣（五审收窄）：只扫描近 7 天归还、无 `OVERDUE-{Loan_ID}` 流水的借出逐笔重试扣分，
  Event_Key 幂等保证已扣不重复；40401 /「分数低于罚分」按永久失败跳过，
  可重试失败留待下一轮继续收敛
