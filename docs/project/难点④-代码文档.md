## 〇、业务规则（组长确认）

> 三审要求：扣分额度和触发时机必须与组长确认，确认后统一 PRD、映射文档、实现和测试。

**超时归还扣 2 分、归还确认只扣一次**（按正式 PRD，组长确认）。

- **触发时机**：归还时（STU-26 归还成功且 `Due_Time < Return_Time`）。
- **额度**：固定按次扣 2 分，与逾期天数无关。
- **扣分入口**：统一走信用分公共服务 `ICreditService.DeductAsync`（难点②合并服务），
  - `Event_Key = OVERDUE-{Loan_ID}`：同一笔借出只扣一次（`UK_D_CREDIT_LOG_EVENT` 唯一约束兜底）；
  - 同一学生的扣分经 `D_STUDENT` 行锁（`SELECT ... FOR UPDATE WAIT 5`）串行化；
  - 跌破 60 分冻结线时由信用分服务统一发冻结通知（Notification_Type='信用'），语义不丢失。
- **逾期巡检不再扣分**：`SP_Check_Overdue` 只给借款人发逾期提醒（'系统' 通知，同笔借出同日一条），
  由此"归还 × 巡检并发"的扣分写方只有一个（归还路径），配合 Event_Key 幂等，只产生一次目标扣分。

## 一、架构概览

### 业务流程

```
学生端（STU-24~27）
  │
  ├─ GET  /api/shared-items                       → 查询可借物品（状态=正常 + 库存>0）
  ├─ POST /api/item-loans  (Idempotency-Key 必填)
  │     → SP_Borrow_Item → 幂等/内容比对 → 信用分≥60？→ 原子扣库存(Available_Qty-1) → 写借出记录(期24h)
  │     → 返回 (rc, loanId)
  │
  ├─ POST /api/item-loans/{loanId}/return
  │     → SP_Return_Item → 原子写归还时间(校验归属) → 库存+1 → 返回逾期天数
  │     → 超期？→ ICreditService.DeductAsync(-2, Event_Key=OVERDUE-{loanId})  ← 统一扣分入口
  │
  └─ GET  /api/students/{studentId}/item-loans?page=&pageSize=
        → 本人校验(403) + 分页返回借还记录

宿管端（DORM-29~30）
  │
  ├─ GET  /api/repair-materials                    → 查询耗材库存
  └─ POST /api/repair-tickets/{ticketId}/materials (Idempotency-Key 必填)
        → SP_Consume_Material → 幂等/内容比对 → 原子扣库存(Stock_Qty-n) → 写消耗记录

定时任务
  └─ 每15分钟: SP_Check_Overdue → 扫逾期未归还 → 发逾期提醒（不扣分）
```

### 并发保护与幂等

| 层 | 机制 | 说明 |
|---|---|---|
| 借出/出库 | `UPDATE WHERE Available_Qty > 0 / Stock_Qty >= n` + `SQL%ROWCOUNT` | 原子扣减，无需显式加锁 |
| 幂等快路径 | 同 `Idempotency_Key` 已存在 → 读取原记录并**比对完整请求内容** | 内容一致返回原结果；不一致返回业务错误码（借出 rc=5 / 出库 rc=3） |
| 并发重放 | 唯一索引 `UK_D_ITEM_LOAN_IDEM` / `UK_D_REPAIR_MAT_USE_IDEM` 兜底 | INSERT 撞唯一索引 → `ROLLBACK TO SAVEPOINT` 撤销库存扣减 → 重读胜者记录比对内容 → 返回原结果或冲突码 |
| 归还 | `UPDATE ... WHERE Return_Time IS NULL AND Student_ID = p_Student_ID` | 原子守门：同一 Loan_ID 只能归还一次，且防跨用户枚举 |
| 逾期扣分 | `Event_Key = OVERDUE-{Loan_ID}` + `UK_D_CREDIT_LOG_EVENT` + `D_STUDENT` 行锁 | 统一入口串行化，只扣一次 |
| 巡检提醒 | 同笔借出同日一条（Title + Content 内嵌 Loan_ID 去重） | 巡检不再触碰信用分表 |

### 事务边界

```
共享物品库存（D_Shared_Item.Available_Qty）← 李昂（难点④ SP_Borrow_Item / SP_Return_Item）
共享物品主数据（D_Shared_Item.* 增删改）    ← 刘鸿铭（DORM-48/49）
                                          两者通过 SP 接口隔离，不直改对方数据
信用分（D_Credit_Account / D_Credit_Log）  ← 难点②信用分公共服务（唯一写方）
                                          难点④只读信用分做借出闸门、只通过
                                          ICreditService.DeductAsync 发起扣分
```

### 2.3 存储过程：SP_Borrow_Item

**功能**：幂等检查（含内容比对）→ 信用分闸门 → 原子扣库存并写借出记录；并发重放由唯一索引兜底。

**参数**：

| 参数 | 类型 | 说明 |
|---|---|---|
| p_Item_ID | NUMBER | 共享物品 ID |
| p_Student_ID | VARCHAR2 | 借出学生学号 |
| p_Idempotency_Key | VARCHAR2 | 幂等键（应用层强制必填） |
| p_Result_Code | OUT NUMBER | 0=成功, 1=物品不存在, 2=物品停用, 3=库存不足, 4=信用分不足（低于60）, 5=幂等键已使用且请求内容不一致 |
| p_Loan_ID | OUT NUMBER | 借出记录 ID（rc=0 时有效，幂等重放返回原 ID） |

**处理流程**：

1. 幂等快路径：同 Key 已存在 → 比对 `Student_ID + Item_ID`
   - 一致 → rc=0 返回原 `Loan_ID`；不一致 → **rc=5**（明确业务错误）
2. Fail-fast 校验：物品存在？→ 状态=正常？→ 库存 > 0？→ 信用分 ≥ 60？（只读闸门，不扣分）
3. `SAVEPOINT sp_borrow` → `UPDATE ... SET Available_Qty = Available_Qty - 1 WHERE Available_Qty > 0`
4. `SQL%ROWCOUNT = 0` → rc=3
5. `INSERT D_Item_Loan`（Due_Time = SYSDATE + 1，24 小时后到期，写入 Idempotency_Key）
6. `DUP_VAL_ON_INDEX`（并发同 Key 重放）→ `ROLLBACK TO sp_borrow` 撤销库存扣减 →
   重读胜者记录（Oracle 保证唯一冲突可见时胜者已提交）→ 内容比对 → rc=0 返回原 ID 或 rc=5
7. COMMIT

**信用分阈值**：Current_Score < 60 → 冻结，拒绝借出。阈值对齐 `D_Credit_Account` 的冻结线。

### 2.4 存储过程：SP_Return_Item

**功能**：原子写归还时间（校验归属）→ 库存 +1 → 输出逾期天数。**不触碰信用分表。**

**参数**：

| 参数 | 类型 | 说明 |
|---|---|---|
| p_Loan_ID | NUMBER | 借出记录 ID |
| p_Student_ID | VARCHAR2 | 归还学生学号（跨用户归还拦截） |
| p_Result_Code | OUT NUMBER | 0=成功, 1=借出记录不存在/已归还/非本人 |
| p_Overdue_Days | OUT NUMBER | 逾期天数（0=未逾期），供应用层判定是否扣分 |

**处理流程**：

1. `UPDATE D_Item_Loan SET Return_Time = SYSDATE WHERE Loan_ID = p_Loan_ID AND Return_Time IS NULL AND Student_ID = p_Student_ID`（原子守门）
2. `SQL%ROWCOUNT = 0` → rc=1
3. 库存回加：`UPDATE D_Shared_Item SET Available_Qty = Available_Qty + 1`
4. `SYSDATE > Due_Time` → `p_Overdue_Days = TRUNC(SYSDATE - Due_Time)`
5. COMMIT

**扣分位置**：应用层 `InventoryTxnService.ReturnItem` 在 SP 返回 rc=0 且逾期时，
调用 `ICreditService.DeductAsync`（ScoreChange=-2，Event_Key=`OVERDUE-{Loan_ID}`）。
另含 rc=1 补偿路径：若记录确属本人、已归还且逾期，补发扣分（Event_Key 幂等保证最多一次），
覆盖"SP 成功但应用在扣分前崩溃"的窗口。

### 2.5 存储过程：SP_Consume_Material

**功能**：幂等检查（含内容比对）→ 原子扣耗材库存并写消耗记录；并发重放由唯一索引兜底。

**参数**：

| 参数 | 类型 | 说明 |
|---|---|---|
| p_Material_ID | NUMBER | 耗材 ID |
| p_Ticket_ID | NUMBER | 关联报修工单 ID |
| p_Quantity | NUMBER | 消耗数量 |
| p_Idempotency_Key | VARCHAR2 | 幂等键（应用层强制必填） |
| p_Result_Code | OUT NUMBER | 0=成功, 1=耗材不存在, 2=库存不足, 3=幂等键已使用且请求内容不一致 |

**处理流程**：

1. 幂等快路径：同 Key 已存在 → 比对 `Ticket_ID + Material_ID + Quantity` → 一致 rc=0，不一致 **rc=3**
2. `SAVEPOINT sp_consume` → `UPDATE ... SET Stock_Qty = Stock_Qty - p_Quantity WHERE Stock_Qty >= p_Quantity`
3. `SQL%ROWCOUNT = 0` → 回查区分"不存在"(rc=1) / "不够"(rc=2)
4. `INSERT D_Repair_Material_Usage`（写入 Idempotency_Key）
5. `DUP_VAL_ON_INDEX` → `ROLLBACK TO sp_consume` → 重读胜者记录 → 内容比对 → rc=0 或 rc=3
6. COMMIT

### 2.6 存储过程：SP_Check_Overdue

**功能**：扫描逾期未归还借出，给借款人发系统通知提醒。**不扣信用分**
（扣分只在归还路径按次扣 2 分，经信用分统一入口）。

**处理流程**：

1. 游标遍历 `WHERE Return_Time IS NULL AND Due_Time < SYSDATE`
2. 解析借款人账户（`D_User_Account`，状态='正常'），无账户则跳过
3. 同日去重：`D_Notification` 中同 Recipient + Title + Content 内嵌 `Loan_ID` 且当天已发过 → 跳过
4. 插入 `D_Notification`（Notification_Type='系统'，ID 用 `NVL(MAX(Notification_ID),0)+1`，
   因 D_Notification 无序列/触发器）
5. COMMIT

### 3.2 服务接口

**文件**：`backend/Services/IInventoryTxnService.cs`

```csharp
public interface IInventoryTxnService
{
    Task<(int resultCode, int loanId)> BorrowItem(int itemId, string studentId, string? idempotencyKey);
    Task<int> ReturnItem(int loanId, string studentId);
    Task<int> ConsumeMaterial(int materialId, int ticketId, int quantity, string? idempotencyKey);
    Task CheckOverdue();
    Task<List<SharedItem>> GetSharedItems(int? buildingId = null);
    Task<PagedResult<ItemLoan>> GetItemLoans(string studentId, int page, int pageSize);
    Task<List<RepairMaterial>> GetRepairMaterials();
}
```

### 3.3 服务实现

**文件**：`backend/Services/InventoryTxnService.cs`（注入 `AppDbContext` + `ICreditService`）

**写操作**：OUT 参数存储过程使用原生 `OracleCommand` 调用（`CommandType.StoredProcedure`），
处理 `OracleDecimal` → `int` 类型转换。

- `BorrowItem`：返回 `(rc, loanId)` 元组
- `ReturnItem`：
  1. 调 `SP_Return_Item` 得到 `(rc, overdueDays)`
  2. rc=0 且逾期 → `DeductOverdueOnceAsync`：先 `GetStatusAsync` 预检（分数为 0 或账户停用则跳过），
     再 `DeductAsync(new CreditDeductDto { ScoreChange = -2, EventKey = $"OVERDUE-{loanId}", ... })`
  3. rc=1 补偿路径：本人 + 已归还 + 逾期 → 补发扣分（幂等，最多一次）
- `ConsumeMaterial`：返回 rc
- `CheckOverdue`：`ExecuteSqlRawAsync("BEGIN SP_Check_Overdue; END;")`

**查询操作**：`FromSqlRaw` 显式 SQL 别名映射；`GetItemLoans` 用 `SqlQueryRaw` 统计总数 +
`Skip/Take` 分页，返回 `PagedResult<ItemLoan>`（Items/Total/Page/PageSize）。

### 3.4 信用分统一入口（关键）

扣分语义全部由难点②合并的信用分公共服务保证（已由 `CreditServiceTests` 单测覆盖）：

- 幂等：`Event_Key` 已存在 → 内容一致返回原结果；不一致抛 `BusinessException(400, "Event_Key 已存在且请求内容不一致")`
- 串行化：`D_STUDENT` 行锁（`SELECT ... FOR UPDATE WAIT 5`），同一学生扣分串行
- 冻结通知：分数从 ≥60 跌破 60 时发 '信用' 通知（`TryNotifyFreezeAsync`）
