## 4. 时序 / 启动依赖

1. **前置模块稳定后再启动**：退宿清算依赖水电分摊、账单/钱包、快递、共享物品数据，必须等这些前置模块基本稳定后开发/联调（S4）。
2. **settle 顺序固定**：先写 `D_Bed_Allocation.CheckOut_Date`，再调 `SP_Calc_Checkout_Fee`，避免 calc 回退 SYSDATE 造成口径偏差。
3. **事务边界**：`SP_Calc_Checkout_Fee` 内部不 COMMIT，由退宿外层事务统一提交；床位、房间、费用三处要么全成、要么全不成。
4. **两入口防重**：`calc-checkout` 与 `DORM-36 settle` 必须互斥，由 `UK_D_FEE_DETAIL (Fee_ID, Student_ID)` 兜底。
5. **主键生成依赖**：`D_Bed_Allocation` / `D_Checkout_Log` / `D_Leave_Application` 依赖迁移 023 序列+触发器；`D_Parcel_Record` 依赖迁移 024；`D_Utility_Fee` 依赖迁移 026。

## 5. 事务 / 并发 / 幂等约束

- 状态机：`待清算 → 已通过 / 已拒绝 / 已取消`；对外响应可将「已通过」映射为「已清算」。
- 幂等：
  - `UK_D_CHECKOUT_ACTIVE`：同一分配最多一条进行中清算。
  - settle 重复调用：已通过校验后直接返回，不重复调 calc。
  - confirm / cancel 重复调用：按状态幂等返回。
  - 结算侧：`UK_D_FEE_DETAIL (Fee_ID, Student_ID)` 防重复明细。
- 并发：
  - `D_Bed_Allocation.CheckOut_Date` 作为并发令牌，调寝/退宿互斥。
  - confirm / cancel 使用 `Status` 并发令牌 + 并发异常重读。

## 7. 不依赖项（避免范围误扩）

- 报修工单状态不阻塞退宿。
- 违规记录不阻塞退宿。
- SLA 派单不阻塞退宿。
- 信用扣分不是退宿前置依赖（共享物品逾期扣分走公共服务，但退宿只读归还状态）。
