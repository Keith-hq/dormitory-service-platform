## 一、架构概览

### 业务流程

```
每月1号 0:05  → SP_Auto_Deduct(attemptNo=1) → 第1次扣款 → 够则扣，不够记录
每月2号 0:05  → SP_Auto_Deduct(attemptNo=2) → 第2次扣款 → 再试
每月3号 0:05  → SP_Auto_Deduct(attemptNo=3) → 第3次扣款 → 最后一次机会
每月3号 0:10  → SP_Check_Power_Cut          → 3次都失败+电费未缴 → 断电
每分钟        → SP_Restore_Power             → 断电房间全员缴清 → 恢复
```

### 核心规则

- 扣款只看 D_Wallet_Account.Balance，够则全扣，不够一分不扣
- 断电只看电费（Power_Share），水费欠缴不触发断电
- 断电断整个房间（一个人欠费全屋断电），缴费后5分钟内自动恢复
- 幂等保证：UK_D_WALLET_LOG_KEY 防重复扣款，UK_D_FEE_DED_ATT 防重复记录

## 二、数据库层

### 2.1 依赖的表

| 表 | 角色 | 关键字段 |
|---|---|---|
| D_Fee_Detail | 读取 | Detail_ID, Student_ID, Room_ID, Water_Share, Power_Share, Is_Paid |
| D_Utility_Fee | 读取（JOIN） | Year_Month |
| D_Wallet_Account | 读取+更新 | Student_ID PK, Balance |
| D_Wallet_Log | 写入 | Log_ID, Student_ID, Amount, Transaction_Type, Before_Balance, After_Balance, Idempotency_Key UNIQUE |
| D_Fee_Deduction_Attempt | 写入 | Attempt_ID, Detail_ID, Attempt_No(1-3), Result(成功/余额不足), UK(Detail_ID, Attempt_No) |
| D_Room | 更新 | Power_Status(正常/断电) |

### 2.2 存储过程：SP_Auto_Deduct

**文件**：`database/sp/sp_billing.sql`

**参数**：

| 参数 | 类型 | 说明 |
|---|---|---|
| p_AttemptNo | NUMBER | 第几次尝试（1、2、3） |
| p_YearMonth | VARCHAR2 | 账单月份，如 '2026-08' |

**调用方式**：`BEGIN SP_Auto_Deduct(1, '2026-08'); END;`

**处理流程**：

1. 遍历当月所有 Is_Paid='否' 的 D_Fee_Detail（JOIN D_Utility_Fee 获取月份）
2. 读取该学生的 D_Wallet_Account.Balance
3. 余额 ≥ 应付合计 → 扣减 Balance → 写 D_Wallet_Log（Transaction_Type='自动扣款'，Idempotency_Key 防重）→ Is_Paid='是' → 记录 Attempt（成功）
4. 余额不足 → 不扣款，只记录 Attempt（余额不足）
5. 幂等：UK_D_WALLET_LOG_KEY 冲突时静默跳过；UK_D_FEE_DED_ATT 冲突时静默跳过

### 2.3 存储过程：SP_Check_Power_Cut

**调用方式**：`BEGIN SP_Check_Power_Cut('2026-08'); END;`

**处理流程**：

1. 找出当月 Power_Share > 0 且 Is_Paid='否' 的分摊
2. 子查询确认该分摊的第 3 次 Attempt 结果为"余额不足"
3. 将对应房间的 Power_Status 置为"断电"

### 2.4 存储过程：SP_Restore_Power

**调用方式**：`BEGIN SP_Restore_Power; END;`

**处理流程**：

1. 取当前月份（SYSDATE）
2. 扫描所有 Power_Status='断电' 的房间
3. NOT EXISTS 检查：该房间本月是否不存在未缴电费账单
4. 全部缴清 → Power_Status 置为"正常"

## 三、C# 服务层

### 3.1 数据模型

**WalletAccount.cs**：映射 D_Wallet_Account，Student_ID PK + Balance。

**WalletLog.cs**：映射 D_Wallet_Log，含 Amount、Transaction_Type、Before_Balance/After_Balance、Idempotency_Key。

**Room.cs**：新增 `PowerStatus` 属性，映射 Power_Status 列。

### 3.2 服务接口

**文件**：`template-backend/Services/IBillingService.cs`

```csharp
public interface IBillingService
{
    Task AutoDeduct(int attemptNo, string yearMonth);
    Task CheckPowerCut(string yearMonth);
    Task RestorePower();
    Task<decimal> GetBalance(string studentId);
    Task<List<WalletLog>> GetWalletLogs(string studentId, string yearMonth);
    Task<string> GetPowerStatus(int roomId);
}
```

### 3.3 服务实现

**文件**：`template-backend/Services/BillingService.cs`

三个存储过程调用方式与 FeeSharingService 一致：`ExecuteSqlRawAsync("BEGIN SP_xxx(...); END;", params)`。

查询方法使用 ADO.NET 原生 DbCommand 直接读 Oracle（绕开 EF Core 表映射未对齐的问题）。

## 五、定时任务

**文件**：`template-backend/Jobs/BillingJobs.cs`

| Job | cron | 说明 |
|---|---|---|
| AutoDeductJob(attemptNo=1) | `0 5 0 1 * ?` | 每月1号 0:05 |
| AutoDeductJob(attemptNo=2) | `0 5 0 2 * ?` | 每月2号 0:05 |
| AutoDeductJob(attemptNo=3) | `0 5 0 3 * ?` | 每月3号 0:05 |
| PowerCutJob | `0 10 0 3 * ?` | 每月3号 0:10（扣款后） |
| RestorePowerJob | `0 * * * * ?` | 每分钟 |

attemptNo 通过 `JobDataMap` 传入，一个 Job 类注册三个 Trigger。
