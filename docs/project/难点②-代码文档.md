## 一、架构概览

### 业务流程

```
每月1号 0:05  → SP_Auto_Deduct(attemptNo=1) → 第1次扣款 → 够则扣，不够记录
每月2号 0:05  → SP_Auto_Deduct(attemptNo=2) → 第2次扣款 → 再试
每月3号 0:05  → SP_Auto_Deduct(attemptNo=3) → 第3次扣款 → 最后一次机会
每月3号 0:10  → SP_Check_Power_Cut          → 3次都失败+电费未缴 → 断电
每分钟        → SP_Restore_Power             → 断电房间全员缴清 → 恢复
```

### 核心规则

- 扣款只看 D_Wallet_Account.Balance，够则全扣，不够一分不扣
- 断电只看电费（Power_Share），水费欠缴不触发断电
- 断电断整个房间（一个人欠费全屋断电），缴费后5分钟内自动恢复
- 幂等保证：UK_D_WALLET_LOG_KEY 防重复扣款，UK_D_FEE_DED_ATT 防重复记录

### 2.2 存储过程：SP_Auto_Deduct

**文件**：`database/sp/sp_billing.sql`

**参数**：

| 参数 | 类型 | 说明 |
|---|---|---|
| p_AttemptNo | NUMBER | 第几次尝试（1、2、3） |
| p_YearMonth | VARCHAR2 | 账单月份，如 '2026-08' |

**调用方式**：`BEGIN SP_Auto_Deduct(1, '2026-08'); END;`

**处理流程**：

1. 遍历当月所有 Is_Paid='否' 的 D_Fee_Detail（JOIN D_Utility_Fee 获取月份）
2. 读取该学生的 D_Wallet_Account.Balance
3. 余额 ≥ 应付合计 → 扣减 Balance → 写 D_Wallet_Log（Transaction_Type='自动扣款'，Idempotency_Key 防重）→ Is_Paid='是' → 记录 Attempt（成功）
4. 余额不足 → 不扣款，只记录 Attempt（余额不足）
5. 幂等：UK_D_WALLET_LOG_KEY 冲突时静默跳过；UK_D_FEE_DED_ATT 冲突时静默跳过

### 2.3 存储过程：SP_Check_Power_Cut

**调用方式**：`BEGIN SP_Check_Power_Cut('2026-08'); END;`

**处理流程**：

1. 找出当月 Power_Share > 0 且 Is_Paid='否' 的分摊
2. 子查询确认该分摊的第 3 次 Attempt 结果为"余额不足"
3. 将对应房间的 Power_Status 置为"断电"

### 2.4 存储过程：SP_Restore_Power

**调用方式**：`BEGIN SP_Restore_Power; END;`

**处理流程**：

1. 取当前月份（SYSDATE）
2. 扫描所有 Power_Status='断电' 的房间
3. NOT EXISTS 检查：该房间本月是否不存在未缴电费账单
4. 全部缴清 → Power_Status 置为"正常"

## 七、缴费与钱包接口（2026-08-15 落地）

对应集成测试用例 C3 缴费划扣链路（IT-C3-001 ~ 004）的接口层落地。

### 7.1 存储过程：SP_Manual_Pay（人工缴费，STU-05）

**文件**：`database/sp/sp_wallet.sql`（依赖 sp_billing.sql 的 SEQ_WALLET_LOG，不内联 DDL）

**签名**：

```sql
PROCEDURE SP_Manual_Pay(
    p_Detail_ID       IN NUMBER,     -- 分摊明细 ID（DORM-23 返回的 detailId）
    p_Student_ID      IN VARCHAR2,   -- 缴费学生学号（C# 已校验为当前登录学生）
    p_Idempotency_Key IN VARCHAR2,   -- 幂等键（≤100 字符）
    p_Result_Code     OUT NUMBER
)
```

**结果码**：

- 0 = 成功或幂等重放（同 Key 已成功过 / 并发同 Key 由对方先行提交）
- 1 = 明细不存在
- 2 = 明细非本人（Detail 的 Student_ID 与 p_Student_ID 不符）
- 3 = 余额不足（钱包行不存在同此——缴费不自动开户；并发同 Key 兜底也可能返回）
- 4 = 已缴或明细金额为 0（不同 Key 重复缴 / 无需缴；CK Amount>0 不允许 0 元流水）
- 5 = Idempotency-Key 已被其它交易类型占用

**流程**：幂等重放检查（必须先于 Is_Paid 检查，保证重试终态一致）→ 明细校验（rc=1/2）→ 已缴或 0 元（rc=4）→ SAVEPOINT + 原子扣款（`UPDATE ... WHERE Balance >= due`，ROWCOUNT=0 → 回滚 rc=3）→ 写流水（UK 冲突 → 回滚 rc=0）→ 标记 Is_Paid='是' → COMMIT。

### 7.2 存储过程：SP_Recharge（充值，STU-07）

**签名**：

```sql
PROCEDURE SP_Recharge(
    p_Student_ID      IN VARCHAR2,
    p_Amount          IN NUMBER,     -- 充值金额（>0）
    p_Idempotency_Key IN VARCHAR2,
    p_Result_Code     OUT NUMBER
)
```

**结果码**：

- 0 = 成功或幂等重放
- 1 = 金额为空或 ≤0，或加款后超出余额上限 NUMBER(8,2)
- 2 = 幂等键已被其它交易类型占用
- 3 = 学生不存在（D_Student 无该学号，FK -2291；正常流程 C# 已拦截）

**流程**：幂等重放检查 → 金额校验（rc=1）→ MERGE 自动开户（学生不存在 -2291 → rc=3）→ SAVEPOINT + 加余额（溢出 ORA-01438 → rc=1）→ 写流水（UK 冲突 → 回滚 rc=0）→ COMMIT。

### 7.3 幂等与并发语义（联调必读）

- 幂等键 = `D_Wallet_Log.Idempotency_Key`（UK_D_WALLET_LOG_KEY 唯一约束），与 C# `Idempotency-Key` 请求头同源，≤100 字符。
- 同 Key 顺序重试：重放检查在任何业务校验之前，直接返回 rc=0（例如已缴明细用原 Key 重试返回成功，而不是 rc=4）。
- 同 Key 并发双提交（线性化兜底）：两个会话同时通过重放检查后，后提交者的流水 INSERT 撞 UK，ROLLBACK TO SAVEPOINT 撤销本会话的扣款/加款后返回 rc=0；若后提交者扣款前余额已不足则返回 rc=3。因此**同 Key 重试 rc=0 或 rc=3 均为交易已终态**，余额以钱包查询（STU-06）为准。
- 跨类型 Key 冲突：缴费 SP 返回 rc=5、充值 SP 返回 rc=2（Key 被另一种交易占用），比常规设计多两个码，联调时按上表映射即可。

### 7.5 SP_Auto_Deduct 竞态修复（sp_billing.sql v1.2）

- **问题**：自动扣款游标读到 Is_Paid='否' 后，若人工缴费先完成（扣款 + 标记'是' + 提交），原子 UPDATE 仍会命中同一明细 → 双重扣款（AUTO Key 与人工 Key 不同，不撞 UK）。
- **修复**：原子 UPDATE 的 WHERE 追加 `AND (SELECT Is_Paid FROM D_Fee_Detail WHERE Detail_ID = fee_rec.Detail_ID) = '否'`。人工缴费先锁 D_Wallet_Account 行，自动扣款在其提交后按行锁串行化重读 Is_Paid，不再命中。
- **验证**：test_sp_wallet.sql T15（38 断言，2026-08-15 Oracle 实测 38/38 PASS）；test_sp_checkout_fee.sql 回归 16/16 PASS。

### 7.6 接口层实现要点

- 缴费/充值走 `CommandType.StoredProcedure` + OUT `p_Result_Code` 读结果码（照抄 SlaDispatchService.CallResultCode 模式）；SP 自 COMMIT，C# 不包事务。
- 录账单 Fee_ID 由 023 迁移的序列触发器回填，EF 侧 `ValueGeneratedOnAdd()` + RETURNING 读回（与 Room 同模式）。
- 修改/发布用条件 UPDATE（`ExecuteSqlInterpolatedAsync` + SQL%ROWCOUNT 守门），防"快路径校验后被并发发布抢先"的竞态。
- 控制器级 [Authorize(Policy = DormAdmin)]（账单）与 [Authorize] + JWT 学生身份解析（钱包）；内部调度器为 [ServiceKeyAuth]。
- 单元测试：150/150 通过（新增 52 例：路由/鉴权挂载反射断言、Idempotency-Key 入口校验、rc → 中文消息映射、InMemory 服务层快路径）。
