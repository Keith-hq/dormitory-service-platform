# 一、快速开始（全体通用）
## 1.1 克隆仓库
```
git clone https://github.com/Keith-hq/dormitory-service-platform.git
cd dormitory-service-platform
git checkout develop
```
## 1.2 一键启动 Oracle 容器
```
cd deploy/oracle
copy .env.example .env
# 编辑 .env，填写 ORACLE_PASSWORD
docker compose up -d
```
首次启动需等待 3~8 分钟初始化。查看进度：
```
docker logs -f dorm-oracle-db
```
看到以下日志代表就绪：
```
Pluggable database DORMPDB opened read write
```
## 1.3 验证数据库连接（DBeaver）
| **参数** | **值** |
|---|---|
| 主机 | localhost |
| 端口 | 1521 |
| 连接类型 | Service Name（服务名） |
| 服务名 | DORMPDB |
| 管理员账号 | system / 本地 `.env` 中的 `ORACLE_PASSWORD` |
| 业务账号（统一使用） | `DORM_OPER`；账号和权限以初始化脚本为准 |

# 三、后端开发：在 backend/ 中开发新模块
## Step 1：进入项目
```
cd backend
```
## Step 2：按规范写代码
**对照 docs/development/01-后端开发规范.md，按以下顺序：**
| **顺序** | **步骤** | **参考文件** |
|---|---|---|
| 1 | Models/ 下新建实体类 | Building.cs（[Table] 和 [Column] 注解） |
| 2 | Repository/ 继承 BaseRepository<T> | BuildingRepository.cs（零代码获得 CRUD） |
| 3 | Services/ 写业务逻辑 | BuildingService.cs |
| 4 | Controllers/ 写 REST 接口 | BuildingController.cs |
| 5 | DTO/ 定义入参出参 | BuildingDto.cs |

## Step 3：启动验证
```
cd backend
dotnet run
```
浏览器打开 http://localhost:5000/swagger，确认接口可调用。
## 后端关键约束（必须遵守）
所有接口返回格式统一为 { "code": 200, "message": "...", "data": {...} }
连接字符串禁止硬编码，使用 .NET User Secrets 或本机环境变量
实体字段必须用 [Column("大写列名")] 精确映射 Oracle
依赖注入：每个 Service/Repository 都要在 Program.cs 注册

# 四、前端开发：在 frontend/ 中开发新页面
## Step 1：安装依赖+启动
```
cd frontend
npm install
npm run dev
```
浏览器打开 http://localhost:3000，默认跳转到 /building 楼栋管理页。
## Step 2：按模板写代码
| **顺序** | **步骤** | **参考文件** |
|---|---|---|
| 1 | api/ 下新建接口文件 | building.js（照抄 request 调用方式） |
| 2 | views/ 下新建页面组件 | BuildingList.vue（CRUD 页面模板） |
| 3 | router/index.js 加一条路由 | 参考已有的 /building 路由 |
| 4 | components/ 复用通用组件 | CrudTable.vue（传 columns 数组即可） |

## Step 3：验证
页面数据正常展示 → 新增/编辑/删除均可用
F12 Network 中 /api/* 请求正常返回
数据变化后刷新页面保持一致
## 前端关键约束
所有 HTTP 请求必须用 @/utils/request，不要直接 axios
API 返回 .then(data => ...) 中 data 已是解构后的数据（拦截器自动处理）
列表页优先复用 CrudTable 组件，不要自己写 table
Token 存在 localStorage，由 Pinia store 统一管理

详细步骤参考 docs/development/04-本地完整联调步骤.md，以下是核心流程：

| **步骤** | **操作** | **验收标准** |
|---|---|---|
| 1 | 启动 Oracle 容器 | docker ps 看到 dorm-oracle-db |
| 2 | DBeaver 连接 | 能查到 BUILDINGS 表数据 |

## 全链路数据流
```
Vue 前端 (3000) → /api/* 代理 → ASP.NET (5000) → EF Core → Oracle (1521) → DORMPDB
```
# 六、常见问题速查
| **问题** | **原因** | **解决方法** |
|---|---|---|
| Oracle 连不上 | 容器没启动 | docker ps 确认，没有就 docker compose up -d |
| 端口 1521 被占用 | 本机装过 Oracle | netstat -an \| grep 1521，停掉本地 Oracle 服务 |
| 表不存在 ORA-00942 | 架构师还没建表 | 联系架构师执行 DDL |
| dotnet run 报 Oracle 错误 | 连接字符串不对 | 检查本机 User Secrets 或环境变量中的 Service Name 是否为 DORMPDB |
| 前端 Network Error | 后端没启动 | 先启动后端 dotnet run，确认 5000 端口 |
| npm install 报错 | Node 版本过低 | 需要 Node.js ≥ 18，当前推荐 v20 |
| 组件报错找不到 | 没注册路由/组件 | 检查 router/index.js 中是否添加了路由 |
