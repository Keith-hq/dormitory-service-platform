# 00 — 项目规范总则

> 面向全体成员及agent的**不可违反的工程红线**。
> 本文件是约束性总则；具体操作流程见 `01-后端开发规范.md`、`02-前端开发规范.md`、`03-Apifox接口联调规范.md`、`04-本地完整联调步骤.md`、`05-前端构建与发布规范.md`。

## 一、仓库目录结构

| 路径 | 职责 | Agent 约束 |
|---|---|---|
| `backend/` | 后端 ASP.NET Core 项目（TemplateDormApi），唯一后端开发位置，含测试 `backend/tests/` | 新模块直接在此工程内新增；不得复制目录、新建平行工程 |
| `frontend/` | 前端 Vue 3 + Vite 项目，唯一前端开发位置 | 同上 |
| `database/` | DDL（foundation / extension）、迁移脚本 `ddl/extensions/`、存储过程 `sp/`、结构校验 `verify/` | 结构变化必须新增编号迁移脚本，不回写 foundation 基线；脚本可重建、可重复执行 |
| `deploy/` | Oracle 容器、环境模板、部署说明 | 环境配置变更需团队确认 |
| `docs/` | 正式文档：`project/`（总纲/看板）、`development/`（本组规范）、`operations/`（排错/接入）、`deliverables/`（验收材料） | 公共文档修改需评审；个人笔记不进公共仓库 |
| `template/` | 最初 M1 模板快照留档（`backend/`、`frontend/` 两份原始脚手架） | **只读**，不参与开发与 CI，禁止修改、禁止从中复制代码参与开发 |
| `.github/workflows/` | CI 流水线 | 修改直接影响全团队构建，需团队确认 |

后端调用方向固定为 `Controller -> Service -> Repository / 公共服务 -> Database`；Controller 不直接操作 DbContext，业务模块不复制调度、通知、信用分和文件存储实现。

## 二、工程红线（不可违反）

1. **数据拥有者与事务边界：** 跨模块写入必须明确数据拥有者、接口入口和事务边界；模块不得直接修改其他模块或公共服务的表，只能通过其接口进入。
2. **幂等、重复执行与失败回滚：** 扣款、扣分、预约释放、库存变化和定时任务必须考虑幂等、重复执行和失败回滚；失败时不能留下半成品状态。
3. **状态机：** 状态字段按状态机处理；后端校验合法转移、操作者和业务条件，**不信任前端传入的目标状态**。每个状态机写清初始状态、允许的下一状态、终态、操作者、触发条件、失败原因、是否产生通知/流水/审计、是否允许重试。
4. **数据库变化：** 必须有可重建脚本、字段/约束说明、关系说明和受影响接口清单；手工改库不算完成交付。主键、外键、唯一、非空和检查约束尽量由数据库保证。
5. **合并前证据：** 合并前必须留下与风险匹配的证据：构建、测试、接口联调、数据库结果或风险说明。
6. **结论区分：** 输出结论时区分"已验证事实""设计要求""待确认问题"和"个人建议"，不把假设当事实。
7. **不擅自改写历史、覆盖成员改动、删除远端分支或绕过 PR、测试和分支保护。**

## 三、API 契约权威与变更流程

- **契约唯一权威：** Apifox 中锁定的接口定义（最新导出的 OpenAPI 文件）。后端 Controller 路由、前端 `src/api/`、Mock、测试均以契约为准；冲突时以 Apifox 为准，不用模板代码反推业务设计。
- 统一响应结构 `{ code, message, data }`；路径按 `/api/<resource>` 组织；错误要区分鉴权失败、无权限、参数错误、资源不存在、业务冲突和服务器异常，不能全部返回 200。
- 契约变更流程：① 提出变更原因、新旧字段、影响模块和兼容方案 → ② 架构师在 Apifox 修改草稿并通知前后端负责人 → ③ 同步 Mock、后端 DTO、前端 API 封装和测试 → ④ 评审通过后标记锁定，PR 中关联变更记录。未完成流程不得直接改字段名、状态值或错误格式。

## 四、功能完成定义

一个功能只有同时满足以下条件才算完成：

- 代码在正确的工作分支中，能编译或构建。
- 接口和字段符合锁定契约，鉴权和错误路径已验证。
- 数据库变化有脚本、约束和必要的初始化数据。
- 关键业务有事务、锁和状态流转处理，至少有对应自测记录。
- 页面处理加载、空数据、失败和重复提交状态。
- PR 已通过预筛和架构师终审，并按团队规则进入 `develop`。
- 有测试记录、联调截图或演示证据，后续文档可以引用该实现。
