# 前端构建与发布规范

本文定义 `template-frontend` 的可复现构建、产物验收和部署约定。业务前端从样板复制后沿用同一流程，不手工修改 `dist/`。

---

## 一、构建基线

| 项目     | 约定                                                                 |
| -------- | -------------------------------------------------------------------- |
| Node.js  | `20.19.0`，以 `.nvmrc` 为准；也支持 Vite 声明的 `22.12.0` 及以上版本 |
| 包管理器 | npm 10+                                                              |
| 依赖安装 | CI、验收和发布统一执行 `npm ci`                                      |
| 构建命令 | `npm run check`，依次完成 ESLint、Prettier 检查和 Vite 生产构建      |
| 产物目录 | `template-frontend/dist/`                                            |
| 产物管理 | `dist/` 不提交 Git，由 CI 或发布人员从目标提交重新构建               |

必须使用已提交的 `package-lock.json` 进行干净安装。不得在发布过程中临时升级、降级依赖或改写锁文件。

---

## 二、环境变量

构建配置必须来自部署环境注入，秘密不得写入前端环境文件。所有 `VITE_` 变量都会进入浏览器产物，因此只允许存放公开配置。

| 变量                | 默认值                  | 构建约定                                                                    |
| ------------------- | ----------------------- | --------------------------------------------------------------------------- |
| `VITE_API_BASE_URL` | `/api`                  | 同域反向代理使用相对路径；跨域地址须由部署环境提供                          |
| `VITE_APP_BASE`     | `/`                     | 根路径部署使用 `/`；子路径部署使用以 `/` 开头和结尾的路径，如 `/dormitory/` |
| `VITE_USE_MOCK`     | `false`                 | 仅开发服务器可启用；生产构建固定关闭并剔除 Mock                             |
| `API_PROXY_TARGET`  | `http://localhost:5000` | 仅用于本地 Vite 开发代理，不进入生产包                                      |
| `DEV_PORT`          | `3000`                  | 仅用于本地开发服务器                                                        |

本地个人配置写入被 Git 忽略的 `.env.local`。发布环境应直接注入变量，不能复制开发者的 `.env.local`。

Mock 开关同时受 `import.meta.env.DEV` 限制，任何 `vite build` 都会静态关闭并剔除 Mock。即使开发者的 `.env.local` 保留 `VITE_USE_MOCK=true`，也不会进入生产产物。

示例：部署到站点根路径并通过同域 `/api` 访问后端。

```bash
VITE_API_BASE_URL=/api VITE_APP_BASE=/ VITE_USE_MOCK=false npm run check
```

## 三、标准构建流程

在仓库根目录进入前端样板后执行：

```bash
cd template-frontend
nvm use
npm ci
npm run check
```

构建失败时不得跳过 lint、格式或生产构建。修复源文件后重新执行完整的 `npm run check`。

`vite.config.js` 固定以下产物契约：

- 输出目录为 `dist/`，每次构建前清理旧产物；
- 静态资源写入 `dist/assets/` 并由 Vite 生成内容哈希文件名；
- 生产 sourcemap 默认关闭，避免部署内部源码映射；
- 路由使用 `import.meta.env.BASE_URL`，与 `VITE_APP_BASE` 保持一致。

## 四、产物验收

发布前至少完成以下检查：

1. `npm run check` 全部通过，命令退出码为 `0`。
2. `dist/index.html` 存在，且引用的脚本和样式文件均位于 `dist/assets/`。
3. 产物中不包含 Mock 测试账号凭据或适配器，浏览器请求指向目标环境 API。
4. 使用 `npm run preview` 验证登录页、直接访问业务路由和静态资源加载。
5. 抽查登录失败、登录成功、列表加载、接口 `401` 和退出登录链路。
6. 发布差异中不包含 `dist/`、`.env.local`、密钥或无关后端文件。

本地预览命令：

```bash
npm run preview -- --host 127.0.0.1
```

`preview` 只用于产物验收，不作为生产服务器。

---

## 五、部署约定

部署目标必须提供静态文件服务，并将前端路由回退到 `index.html`。同域部署时，Web 服务器还应把 `/api` 反向代理到 ASP.NET Core 服务，不能让静态文件服务接管 API 路径。

子路径部署需要同时满足：

- 构建前设置 `VITE_APP_BASE=/目标目录/`；
- 将 `dist/` 内容部署到对应目录；
- Web 服务器的 SPA 回退规则保留该目录前缀；
- 验证刷新业务路由不会返回服务器 `404`。

静态资源应长期缓存带内容哈希的文件；`index.html` 应采用短缓存或不缓存，确保新版本入口及时生效。

---

## 六、版本与回滚

组件库的公开入口是 `src/components/index.js`。新增导出属于向后兼容变更；删除导出、重命名组件或修改既有 prop、event、slot 语义属于破坏性变更，必须进入新的主版本。

Tag 只能指向已经通过 `npm run check` 和代码评审的提交。创建 tag 前必须由项目负责人确认 tag 名称、目标提交和发布责任人。

每次发布应保留目标 Git 提交号及对应构建产物。回滚时重新部署上一已验收提交的完整 `dist/`，不得把新旧版本文件混合覆盖。
